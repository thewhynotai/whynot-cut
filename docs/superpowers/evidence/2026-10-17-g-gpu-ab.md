# G-GPU: the live A/B of every media site, CPU vs GPU lane (Phase 4 T4.10 step 8)

Measured on **2026-10-17** by the API-credit lane with `tools/bench_media.py` (snapshot of 8bd6b60) through
`heavy.sh gpu`, on the owner's PC: Lenovo LOQ, i7-14700HX (20 threads), RTX 4060 Laptop 8 GB, Windows 11, the engine's
pinned FFmpeg 7.1 (NVENC / NVDEC). Premiere and After Effects were **not running** (process list checked). The machine
was shared with other sessions' test suites (RAM 71-74 % in the run log; CPU load was not logged in the run, heavy.sh
status around it showed 31-40 %), which slows the CPU lane, i.e. biases toward the GPU.
Inputs (test copies only): the clip = the 56 s `EP02_R02.mov`, the episode = the 34:41 `EP02.mp4`, both from the
scratch copy of `../whynot-test/Dr Sherin Helmy` (the `عميل-تجربة-٣` clips the plan names are 14 s, too short for a
timing; `PODCAST-TEST` holds no media, its EP02 is this same file). Each figure is the median of **3 runs**; SSIM is the GPU output against the CPU output (FFmpeg `ssim`).
Raw numbers: `D:/ClaudeData/Temp/wnc-p4/t410/bench.json` (outside the repo).

## The rule, applied as written
A site keeps `"gpu"` only if the GPU run is **≥ 15 % faster AND SSIM ≥ 0.98**. Every GPU run was **slower** (by 35-50 %:
the engine's jobs are seconds long, so the CUDA / NVENC start-up dominates, and 20 CPU threads encode a 540-wide proxy
fast). SSIM passed where it applies (0.988-1.0), the speed did not. So:

```
SITE_LANES = {"preview_video": "cpu", "reel_candidates": "cpu", "animatic": "cpu", "thumbs": "cpu", "shots": "cpu",
              "grab_frame": "cpu"}
```
`lib/accel.py` carries these values; the GPU lane code stays (a machine class where the A/B says otherwise sets a value
back to "gpu" after its own run). `VT_Q` is unchanged (VideoToolbox is measured on the Mac).
`SITE_LANES` is one global table, so these Windows/NVENC results also turn VideoToolbox off on Macs. Mac lanes are
measured separately at Phase 12; VideoToolbox stays off until then.

## Finals
Motion MP4, libx264 crf 18 vs h264_nvenc -cq 18: NVENC 3.33 s vs libx264 13.89 s (about 4 x faster; 45.8 MB vs 29.9 MB
), but **SSIM 0.99362**, below the 0.995 bar, so finals stay on libx264 crf
18 (the default; no switch, no separate commit). Per `bench_media.final_rule`, the six-frame side-by-side view is made only for a
candidate (SSIM ≥ 0.995), so it was not made.
