# T3.7 evidence: the `claude plugin eval` suite (30 cases) and its pass rates

Date 2026-10-13. Windows 11, Claude Code CLI 2.1.295 (the desktop app's bundled `claude.exe`, found by
`tools/find_claude.py`), logged in to claude.ai (team plan). Everything the cases touch is fictional (the Example
Clinic, Dr. Sample Example, EP12); no real client data, nothing under `D:\WhyNot Clients`, and the real
`~/.whynot-cut` is never used (see "Sandbox" below).

## Eval format facts (verified against the CLI 2.1.295 itself)

The docs site was not reachable from this machine, so the format was read from `claude plugin eval --help`,
`claude plugin eval init --bare` and the schema compiled into the bundled `claude.exe`. The first real run confirmed it.

- **Case** = a folder under `evals/` with `case.yaml` and/or `prompt.md` (+ `graders/*.md`). A folder with neither file
  is not a case, so `evals/_fixtures/` is safe. The `--case` filter is applied **before** parsing, so a filtered run
  does not validate the other cases.
- **case.yaml keys:** `schema_version` (required; current `"1.1"`, major 1), `name`, `description`, `tags`, `plugins`,
  `runs` (default 3, max 50), `context.{scaffold_script, history_file, add_dirs}`,
  `execution.{prompt, max_turns (10), timeout_seconds (300), model, allowed_tools, artifact_publish,
  append_system_prompt, env (EVAL_* keys only)}`, `graders` (≥ 1 after merging), `expected_outcome`.
- **prompt.md frontmatter** may carry the same top-level and execution keys; any other key is an error. It is merged
  over case.yaml, the body becomes `execution.prompt`, and `graders/*.md` are appended (grader name = file stem; a
  duplicate name is an error).
- **Grader types** (strict keys): `regex` (`target`: last_message | trace | files | mock_calls | {source: file, path};
  `match`: contains | not_contains | count:N; `flags`; the body is the pattern, JS RegExp), `tool_used` (`tool`,
  `input_match` regex over the call's JSON input, `min` default 1, `max`), `tool_order`, `file_exists`
  (created files only), `llm` (`focus`, the body is the rubric, 3 judge votes, default judge haiku), `baseline`. All
  take `weight` and `arm: with-only | both`.
- **Ablation:** the default is `with-without` (a no-plugin arm, 2× runs). There, a `tool_used: Skill` grader without
  `arm` is a display-only "plugin fired" indicator. With `--ablation none` it is scored. A should-not-trigger check is
  `min: 0, max: 0, arm: both`.
- **Scoring:** run score = weighted share of graders passed; case score = mean of runs; `--threshold` (default 1.0)
  sets the exit code. "Passed" per run in the JSON = every scored grader passed. Report:
  `aggregate-result.json` (`cases[].arms.with[]` → `passed`, `score`, `graders[]` with `judgeVotes` and the judged
  `evidence`; `aggregates.{casesPassed, overallPassRate}`). With `--json` the per-run progress lines are not printed.
- **Scaffold:** `context.scaffold_script` is a path that must stay inside the case folder (`..` or an absolute path is
  refused). It runs only with `--scaffold`, as `bash <realpath>` (Git Bash on this PC). Its cwd is the run's empty
  `…/claude-eval-XXXX/home/cwd`. Its environment is only PATH, HOME = USERPROFILE = the sandbox home, TMP and TERM.
  It is killed after 120 s, and a non-zero exit scores the run 0.
- **Sandbox:** the agent child gets `HOME` = `USERPROFILE` = the sandbox home, its own `CLAUDE_CONFIG_DIR`, no
  CLAUDE.md, and only the plugin under test. Only Read/Glob/Grep/Skill are granted unless the case lists more *and* the
  operator grants them with `--allow-tools`. A skill's own `allowed-tools` does **not** grant Bash inside a run. The
  agent therefore cannot run `reel`, and the sandbox home has no engine (it sees a fresh machine). PATH is inherited.
- **Mocks:** `evals/mocks/<server>/<tool>.md` stand in for a plugin's MCP server. WhyNot Cut registers no MCP server
  yet, so no mock is shipped (see magnific below).

## What changed in the suite (review 6.1–6.2)

- Every case has a `case.yaml` (schema 1.1, runs 3, `scaffold_script: scaffold.sh`) and a `graders/skill-fired.md`
  (`tool_used: Skill`, `input_match: '"skill"\s*:\s*"(?:whynot-cut:)?(?:<skill>)"'`).
- The `scaffold.sh` sources `evals/_fixtures/example-clinic.sh`. That script builds the fictional `example-clinic`:
  - the `.whynot-client` marker
  - `assets/`: an svg logo, a brand brief and a font note
  - `data/Raw/C0238–C0240.MP4`: 3 s 270×480 clips from ffmpeg `testsrc` + `sine`, ≈45 KB
  - `data/Episodes/EP12.mp4` + `EP12.md` (the episode sheet)
  - the shipped example-clinic reel-profile
  - per case, optionally: a project with words-to-confirm and the medical/religious review, EP12's reels plan,
    approved reels, a panel approval (`plan-approval.json` `via: panel`), reference edits, or a Hugo site
- **ffmpeg:** the scaffold uses `ffmpeg` on PATH, else the first `ffmpeg*` binary in a PATH folder. On this PC that is
  the engine runtime's `imageio_ffmpeg/binaries` folder, put on PATH for the run.
- Regex graders check concrete commands in the final answer. Each is a real `reel` command/option of the current
  parser, checked by hand and by the static check below:
  - `reel inbox`, `reel client-init`, `reel audio-clean`, `reel handoff`, `reel settings`, `reel motion-plan`,
    `reel preview-video`, `reel publish-check`, `reel ppro-status`

  - `reel reels-select … --as motion`, `reel reels-select … --by delegated`
  - `reel (next|qc)`, `reel (doctor|setup)`
  - Other regex graders: `HbA1c`, `G03`/`G05`, `C0238`, `PlayerDebugMode`, `bin/reel`, an Arabic-reply check, and
    `not_contains` `Gate 0/1/2` on the editor-facing text.
- Every case except the negative one has `append_system_prompt` saying the session has no shell. It asks for the exact
  plan (steps, `reel` commands in order, where it stops) and an honest "nothing ran". Each rubric starts with a matching
  judge note. Without this, the agent correctly answered only "nothing can run, use /whynot-cut:start" (first full
  attempt).
- **16 new cases:**
  - negative-hugo-assets: should not trigger. Write/Edit are granted, the guard must not block, and `_hero.scss` must be
    created.
  - edit-, revise- and status-arabic-only
  - fix-audio-only, handoff-for-editor, help-cheat-sheet, preferences-stop-asking
  - new-client-reference-style, transcript-words-to-confirm, medical-religious-approvals, motion-revision
  - wrong-reel-on-path (G66), gate0-delegation ("you choose" → `--by delegated`)
  - magnific-broll-pending: a placeholder, tag `pending`, Skill grader `min: 0`, until Phase 5 adds skills and mocks
  - panel-approval-sessionstart (Addendum C). Checked offline first: the T3.4 SessionStart hook on this scaffold
    prints "Panel approvals not built yet: Mona approved C0238 in Premiere at 08:30".
- The 14 old prompts now point at the fixture folder. "Her audio" became "his audio" to match the fixture doctor.
- protect-client-sources runs inside the client folder, so the session context applies. Its Skill grader is
  record-only (`min: 0`), because no skill is expected for a refusal.
- **Static check (not committed, scope):** `tests/test_evals.py` checks:
  - every case.yaml, prompt.md and grader against the runner's key sets
  - that skill names exist
  - that regex `reel <cmd> --flag value` matches the real parser (via test_structure)
  - that scaffolds only call fixture functions
  - and it has seeded-mistake tests

  It passed (5/5) before it was taken out of the tree. It is kept for the executor with a one-line `package.py` patch
  that keeps `evals/results/` out of the zip (review 6.3).

## How it was run

From the plugin folder. PATH had the engine's ffmpeg folder added and the installed 2.2.1 plugin's `bin/` removed:
from inside a Claude Code session that `bin/` is on PATH, and the child would otherwise find the old `reel`.

```bash
claude plugin eval . --runs 3 --ablation none -j 3 --scaffold --trust-plugin --no-publish \
  --allow-tools Write Edit --max-cost-usd 20 --output-dir <scratch> --json <scratch>.json
```

`--ablation none` keeps the `tool_used: Skill` grader scored and halves the usage. `--allow-tools Write Edit` reaches
only the negative case, the only one listing those tools.

Re-runs used `--case <name> --judge-model sonnet`. The runner's own authoring guide recommends a sonnet-tier judge;
the haiku judge failed several correct answers unanimously.

    not exist".
