"Before → after": hooks.json is unchanged by this fix round, because every assets/data/marker/prefs write on any drive,
on UNC, through an 8.3 alias and through an alias of the client folder already invoked the guard. The review's
expectation (a `//` pattern fails when the path is not relative to the session's root) did not hold in CLI 2.1.295,
neither from a D: session nor from a C: session.

## Other findings

- The CLI normalises a Write's `file_path` to backslashes before the hooks see it (forward-slash paths arrived as
  `D:\…`), so D3/C7/U3 behave like their backslash forms.
- `*`-prefixed (raw-path) rules: P12 `*.whynot-*` and P13 `*After Effects*` matched; P14 `*after effects*` did **not**
  (raw matching is case-sensitive); the raw `*\assets\*`-style rules (P04–P11) matched only for paths under the
  session's cwd (nothing on other drives, UNC paths or aliases), and `*\assets\*` also over-matched `Assets2`. They
  would add nothing and over-match, so none were added.
- S3 and J2 cannot be caught by any path pattern: the path names no source folder. Documented in `hooks/README.md`
  as a known miss (threat model: accidental damage, not a sandbox). An alias of the client folder or of a folder above
  it is matched (S1, S2, J1).
- Scratch left behind: `whynot-test\_t34_ifprobe\` (a marked scratch client; the guard rightly refuses deleting
  inside its sources, so it stays in the test area). The subst drives and junctions were removed.
