# T3.4 live evidence: session ids, /clear and the writer lease; hook `if` filters; CwdChanged; Stop gate

Date 2026-10-13. Windows 11, Claude Code CLI 2.1.295 (the desktop app's bundled `claude.exe`, found by
`tools/find_claude.py`), Git Bash hooks.

## How it was run

The bundled CLI's own login had expired, so no real model was used. Instead the CLI ran headless (`-p`, also
`--input-format stream-json` to send `/clear` between two user messages) against a **scripted stand-in for the Messages
API** on 127.0.0.1 (`ANTHROPIC_BASE_URL`, a dummy key; scratch `fakeapi.py`). The stand-in returns exactly the tool calls
of a script (Write/Edit/NotebookEdit/Bash/PowerShell) and logs every request body, so we can see what context reached
the "model". Plugins: `--plugin-dir whynot-cut` (the 3.0 tree) and small probe plugins that log each hook's stdin payload
and its `CLAUDE_CODE_SESSION_ID` / `CLAUDE_PID` environment; the installed 2.2.1 plugin was disabled with
`--settings '{"enabledPlugins":{"whynot-cut@thewhynot-ai":false}}'`. Every run used a scratch cwd; the live run of the
real plugin had HOME/USERPROFILE, `CLAUDE_CONFIG_DIR` and `WHYNOT_HOME` in a scratch folder (the real `~/.whynot-cut`
was not touched: `plugin-root.json` was written only in the scratch home). The client folder was a fictional "Test
Clinic" in the scratch folder.

## 1. Session id: SessionEnd payload vs `CLAUDE_CODE_SESSION_ID`

| What | Value seen |
|---|---|
| SessionStart payload `session_id` (startup) | `48464027-…` |
| `CLAUDE_CODE_SESSION_ID` in Bash (first turn) | `48464027-…` |
| `CLAUDE_CODE_SESSION_ID` in the hook processes | `48464027-…` |
| SessionEnd payload `session_id` (reason `clear`) | `48464027-…` |
| `CLAUDE_PID` (hooks and Bash) | `138712` (the CLI process), unchanged for the whole run |

**The SessionEnd payload's `session_id` equals the `CLAUDE_CODE_SESSION_ID` Bash sees** (same in 4 runs).
`CLAUDE_SESSION_ID` is not set.

## 2. What `/clear` does

Order seen (stream-json, three messages "first", "/clear", "second"):

1. `SessionEnd` reason `clear`, payload `session_id` = A (`48464027-…`);
2. `SessionStart` source `clear`, payload `session_id` = **B** (`0c56fcf9-…`), new transcript;
3. Bash in the next turn: `CLAUDE_CODE_SESSION_ID` = **B**, `CLAUDE_PID` = **the same process** (138712).

So /clear is a new session id inside the same Claude Code process. For the writer lease (`output/.whynot-lock`, T1.8):

- A's lease (holder pid = `CLAUDE_PID`) is released by `session_end.py` when SessionEnd completes. Seen live:
  `session_end.py` (via `run_python.sh`) took ≈0.45 s and logged "released at the end of session A"; B's next
  writing command found no lock.
- **Gap:** SessionEnd hooks share a **1.5 s budget** (docs; a plugin hook's own `timeout` does not raise it). On a
  loaded machine `run_python.sh` + Python can miss it, and then A's lease survives with a **live holder** (the same
  `CLAUDE_PID`), so before this task B was refused for up to 2 h: locked out of its own client.
- **Fix (writer_lock.same_process):** a lease whose holder is this command's own Claude Code process (same pid, same
  process start time, this computer) is this session's. The next writing command takes it over under the new id with a
  pipeline.log line; SessionStart does not warn about it; `reel lock --status` says `mine`. Live check: after /clear we
  put A's lease back (simulating a SessionEnd cut short) and B's writing command succeeded:
  `writer lock: session 0c56fcf9-… continues the lease of session 48464027-… (same Claude Code process 138712: /clear
  or /resume)`. Another Claude Code process (another session) is still refused (unit tests).

## 3. `if` filters on the file tools

Probe runs (one handler per pattern, each logging when it ran):

- The rule's tool must be the call's tool: `Edit(//**/data/**)` **never** ran for a `Write` call; `Write(…)`,
  `Edit(…)` and `NotebookEdit(…)` each match only their own tool.
- `//` = absolute. Relative `**/assets/**` did not match a write to `…\outside\assets\d.txt` outside the cwd;
  `//**/assets/**` matched it.
- Matching is case-insensitive on Windows (`**/ASSETS/**` matched `assets` and `Assets`); character classes work
  (`[Aa][Ss]…`), so the patterns also hold on macOS.
- `X/**` also matches a file named `X` (`//**/[Dd][Aa][Tt][Aa]/**` matched a file `other\data`;
  `//**/*.whynot-*/**` matched `.whynot-client` and `output\.whynot-lock`; the After Effects pattern matched both the
  prefs folder and a loose `Adobe After Effects 24 Prefs.txt`).
- Handlers with the same command and different `if` are not merged before the filter.

Live run of the real plugin (debug log): a Write to `live\other\note.txt` and to `Test Clinic\output\notes.md` logged
"Skipping hook due to if condition … not matching" for all 12 handlers and started **no process**
(`permissionDecisionMs` 76 ms for the second write, whole tool 121 ms). Writes to `Test Clinic\data\Raw\new.txt` and
`Test Clinic\.whynot-client` ran the guard and were refused ("the client's source folder … is read-only").

Latency, measured directly on this PC: `run_python.sh` + `guard.py` for a Write outside sources = **261 ms median**
(220 ms min, 10 runs), now **0** (no spawn); a guarded write cost ≈340 ms of hook time in the live run.

## 4. CwdChanged

Per the hooks reference, CwdChanged reads only `watchPaths` and `systemMessage` (no `additionalContext`) and has
`CLAUDE_ENV_FILE`. So the hook writes the context to `${CLAUDE_PLUGIN_DATA}/pending-context/<session>` and the guard
adds it to Claude's next Bash/PowerShell call as PreToolUse `additionalContext` (seen live: a PreToolUse
`additionalContext` reached the request body; no extra process).

On this PC the event **never fired**: the Bash tool logs `shell cwd read-back is not readable; ignoring` after every
command, so `cd` does not persist (the next `pwd` is the project folder again) and no CwdChanged is raised; a
PowerShell `Set-Location` persisted within PowerShell but raised no CwdChanged either. The CwdChanged path is covered
by unit tests (payload on stdin) and stays to be seen live where the cwd read-back works (macOS, or a later CLI).

## 5. Stop evidence gate

With `evidence_gate: on` in the client's preferences, a turn that ran `reel … ppro-build` and ended "The reel is ready
for review." was sent back: `Hook Stop … {"decision": "block", "reason": "WhyNot Cut evidence gate: …"}` and the
reason reached the next request. Off (the default): `stop_gate.sh` exits using bash builtins only (≈39 ms bash start
measured, no Python).
