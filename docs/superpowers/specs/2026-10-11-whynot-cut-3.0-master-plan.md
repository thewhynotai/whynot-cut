## 1. Goal, success criteria, scope

### 1.1 Goal
Turn WhyNot Cut 2.2.1, which already works live on Windows (Premiere 26.5.2, After Effects 26.5), into a
**finished, robust, easy, branded product**. Any video editor installs it on **Windows or macOS** in about 6 steps
with no admin and no registry commands. They drop raw material into a client folder and get native Premiere / After
Effects projects, previews, QC proof and publish copy. A native **WhyNot Cut panel inside Premiere** (and After
Effects) shows progress, takes approvals and shows QC frames. Material from **Magnific** is used only when the
content needs it, under budget and licence rules.

### 1.2 Success criteria (Definition of Done is in §10)
1. **One destination.** `Editing Plugin\WhyNotCut\` (git repo) is the only source of truth. `dist/` holds the release:
   one plugin zip that contains everything, the installers, `.ccx`, `.zxp` and the Arabic PDF.
2. **No known Critical/Important defects.** Every engine **CR-/IM-** and structure Critical/Important finding is
   fixed with a regression test, or explicitly re-classified with a reason in `PROGRESS.md`.
3. **Native Premiere plugin.** The UXP plugin builds a reel with the same read-back checks and QC frame sheet as the
   CEP path. The panel approval is recorded as an editor approval.
4. **After Effects.** Motion mode builds through a **signed** panel with PlayerDebugMode **off**.
5. **Install.** One-liner install works on a clean Windows user account (no Python, no Git). On macOS it is verified
   live if a Mac is available (H6); if not, the release says so.
6. **Magnific.** A needs-driven, approved, licensed asset flow. With Magnific absent, the pipeline still completes.
7. **Arabic PDF guide.** Branded, RTL-correct, covers install → first edit → podcast → motion → revise → handoff →
   troubleshooting.
8. **Tests and validation.** Full unit suite green, `claude plugin validate --strict` clean, eval suite with
   `tool_used` graders green.

### 1.3 In scope
Everything in §7, Phases 0–11.

### 1.4 Out of scope (backlog, §9)
- Uploading to YouTube or other platforms.
- pyannote diarization, raw multicam editing, split-screen.
- Motion videos longer than 180 s, and 4:5 / 1:1 motion formats.
- Designer look packs.
- The After Effects UXP port, unless AE 27 UXP is publicly available during execution (T6.8).
- Resuming the paused real client job (Dr Sherin EP02): that is client work, not plugin development. Use copies
  under `whynot-test/` for tests.

## 6. Execution model, QC gates, stop rules

### 6.1 Answer to the owner's question
**One autonomous run, internally phased.** Claude takes this file and keeps working until everything is done. It
works through Phases 0–11 in order, and each phase must pass its QC gate before the next starts. This combines the
owner's "don't stop" with the owner's "test and QC each phase".
- **Checkpoint.** `WhyNotCut/PROGRESS.md` is updated after every task (done/blocked, commit hash, test count) and every
  decision. After a context compaction or a usage-limit pause, resume from it. Never re-derive finished work.
- **Commits.** One commit per task on branch `release/3.0` (conventional messages; trailer per the session's
  attribution reminder). A tag `v3.0.0-p<N>` after each passed phase gate.
- **Parallelism.** Subagents run in parallel only on disjoint files, or read-only. One writer per file set. No extra
  worktrees: the owner wants one folder.

### 6.2 QC gate (run at the end of every phase; all must pass)
1. **Unit suite:** 0 failures, 0 errors. Record the test count, which must never decrease, and the duration.
2. **New behaviour has tests:** every task that changes behaviour adds a test that failed before (TDD).
3. **Validation:** `claude plugin validate --strict` passes on the marketplace and the plugin. Use the bundled CLI:
   `tools/find_claude.py` resolves `%APPDATA%\Claude\claude-code\*\*\claude.exe` or the macOS app bundle.
4. **Static checks:**
   - `python -m compileall -q whynot-cut/engine whynot-cut/hooks`;
   - `node --check` on every CEP `.js`;
   - `tsc --noEmit` on `adobe/premiere-uxp` and `adobe/panel-ui`;
   - JSON Schema self-validation.
5. **Independent review:** a fresh-context reviewer subagent (`superpowers:requesting-code-review`, or the
   `code-review` skill at `high`) on the phase diff. There must be **0 Critical and 0 Important** open. Minor findings
   are either fixed or logged in `PROGRESS.md`.
6. **Live checks** listed in the phase (Premiere/AE/installer). The proof is produced **now**, and the frame sheets
   are **viewed**. `*_BUILT` or exit 0 is not proof (edit skill, Gate 2).
7. **Docs:** CHANGELOG `## 3.0.0 (unreleased)` updated; skills and README match the behaviour.
8. **Record:** `PROGRESS.md` phase summary (Verified / Not verified / Needs you), commit, tag.

**Fix loop:** a failing gate item goes back to the owning task. **After 3 failed loops on the same issue, stop that
item**, write a blocker report in `PROGRESS.md` (what was tried, root-cause hypothesis, options), and continue with
independent work. If the blocker gates later phases, stop and tell Yunus.

### 6.3 Gap log
Any new defect found while working gets an ID `G70+` in `PROGRESS.md`: symptom, root cause, fix commit or "open".
This keeps the owner's "find gaps, analyse, add them" practice.

## 8. Risk register

| Risk | Impact | Mitigation |
|---|---|---|
| UXP API gaps or churn (no audio mono-pair API, caption-track creation, razor; 27.0 type changes) | Panel or build parity breaks | Spike first (T6.4); per-op routing to CEP; pinned `minVersion`; a smoke test per Premiere update; XML import for the base timeline |
| A self-signed extracted ZXP doesn't load with PlayerDebugMode off | Users still need PlayerDebugMode | Try UPIA install of the ZXP; if both fail, keep the developer path and document it clearly. The installer offers a consented checkbox (installer R.2 step 7) |
| UXP → localhost WS quirks (IPv6, domain matching, Windows reliability) | The panel can't talk to the engine | Use `127.0.0.1` literals; HTTP long-poll fallback; file-queue fallback |
| UPIA needs Creative Cloud desktop signed in | `.ccx` install fails | Double-click `.ccx` fallback; doctor detects; UPIA logs in diagnostics |
| macOS not testable (no Mac) | Mac users hit untested paths | H6; macOS CI on GitHub runners; the release states the gap honestly |
| Windows Smart App Control blocks unsigned Python/ffmpeg binaries | Engine doesn't start | Detect SAC in preflight; a smoke test during install; a clear message |
| Usage limits or compaction mid-run | Lost progress | `PROGRESS.md` + a commit per task; resume rules (§6.1) |
| Magnific licence and spend (credits, non-transferable files) | Cost, legal | Zero auto-spend, approvals, hook, manifest, handoff exclusion |
| Skill descriptions dropped by the listing budget | Skills don't trigger | ≤ 4,000 chars total + a test + `tool_used` eval graders |
| Arabic paths and usernames (CTranslate2/OpenCV narrow paths) | Transcription or faces fail | Doctor warning + `WHYNOT_HOME=C:\whynot` suggestion; tests with Arabic paths |
| Local daemon = new attack surface | Local abuse | Token, loopback, Host/Origin checks, schema-only commands, no script endpoint, audit log; security review T8.2 |
| Adobe's own Premiere AI Assistant overlaps | Competitive | WhyNot Cut's moat: client brand systems, Arabic motion, approval gates, evidence QC; keep those first-class |
| CEP sunset (Premiere stops accepting new CEP Marketplace submissions Dec 2027; CEP off by default Dec 2028, removed Dec 2029) | AE path ends | Backlog item with a deadline: AE UXP port when AE 27 UXP is public |
