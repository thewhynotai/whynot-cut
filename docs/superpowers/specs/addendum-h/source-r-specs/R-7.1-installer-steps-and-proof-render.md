# R-7.1 Installer step state machine (key, verify, resume), sha256 for every download, doctor proof render

Phase 7. Owners: installer track (state machine, downloads), executor (`reel doctor` proof render).
"Key" means a step's idempotency key, not a licence key (no licence keys in 3.0).

## Source-R behaviour

- **Setup steps** in order: folders → packages → render browser → FFmpeg → fonts → models → transcription runtime.
- Each step has a fingerprint of its pinned inputs and a verification check; a step whose fingerprint matches and
  whose check passes is skipped. Setup runs as a detached background worker with a state file and status polling.
- Every download is checked by **sha256 and byte count**, written to a `.partial` file and renamed on success, with
  retries when antivirus holds the file. Some runtime models trust the server's tag on first use.
- **Doctor**: a quick check (platform, tools, clean working copy) and a full check that renders a short test video with
  the user's name, colours and ending through the delivery gates.
- Windows only.

## Our version

### Installer core (T7.1)
- Steps (ours): runtime → engine → FFmpeg → fonts (OFL, from upstream) → transcription models → aligner → Adobe
  plug-ins → checks. Each step has a `fingerprint` = sha256 of its pins (versions, URLs, file hashes, target paths) and
  a `check` = a cheap real test (file hashes, `--version`, import test). (Generic installer ideas; our names.)
- State in the engine home (`state.json`, atomic writes): `pending | running | done(fingerprint) | failed(reason)`;
  resume after a reboot or a crash skips steps whose fingerprint matches and whose check passes.
- **Every** download: sha256 + byte count from our lock, `.partial` + rename, retry with back-off when a file is locked
  (AV), never trust-on-first-use; a corrupted file is deleted (a file, never through a link) and re-downloaded.
- Mac first (arm64, no Homebrew), Windows per-user; GPU components (cuBLAS / MLX) as optional steps; no git and no Node
  in the customer install.

### Doctor proof render (`reel doctor --proof`)
- A 3-second branded test sequence built in Premiere through the bridge **in a temporary project under the engine
  home** (never in the editor's open project; removed afterwards; skipped with one line while Premiere is busy,
  `host_busy`) (client logo, colours, fonts, an Arabic line
  and an English line, a caption in the client's caption look), plus an AE comp read-back with the client's fonts.
- It passes through our gates (safe zones, contrast, fonts present, Arabic shaping) and shows the result in the
  panel as one line and two stills.
- Fail-open: a missing Adobe app or bridge gives a plain line and skips the proof, never a crash (G10).

## Acceptance
Kill mid-install → resume skips verified steps; a corrupted download is re-fetched; every lock entry has sha256 +
bytes; doctor renders the branded proof and reports in one line; Mac and Windows paths tested with fakes.
