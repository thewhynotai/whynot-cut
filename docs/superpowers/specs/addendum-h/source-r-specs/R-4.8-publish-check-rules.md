# R-4.8 Stricter publish-check: no repeated spoken sentences, no cross-platform duplicates, no filler hashtags

Phase 4, Task 30. Owner: executor (`publish.py`, publish-writer agent text).

## Source-R behaviour

- A separate post text per platform (Instagram, TikTok, YouTube Shorts).
- The search phrase sits in the first visible line of the caption.
- The copy never re-says the spoken sentences; no invented numbers; no engagement bait; no generic "for you" style
  hashtags.
- Writing styles: short, educational, storytelling; the dialect follows the speech; alt text with a length limit; a
  pinned comment.
- A checker rejects copy that repeats transcript sentences and copy duplicated across platforms.

## Our version

`reel publish-check` gains four rules (on top of today's limits in `platform-limits.json` and the medical/religious
review):
1. **No spoken-sentence repeat**: any 6-word n-gram (normalised tokens, Arabic rules of R-4.3) shared with the
   transcript, or a caption whose token overlap with any single transcript sentence is ≥ 0.7 → refused, with the
   offending span quoted and the fix ("قول الفكرة بكلام جديد بدل ما تكرر الجملة اللي اتقالت").
2. **No cross-platform duplicate**: two platforms' captions with token Jaccard ≥ 0.8 → refused ("كل منصة محتاجة نص
   مختلف").
3. **No filler hashtags**: a list in config (`publish-rules` block: generic reach hashtags in AR and EN, editable per
   client) → refused with the tag named.
4. **First-line limits per platform**: the search phrase (from the publish-writer brief) must start within the
   platform's first-line limit (config per platform) → otherwise a warning with the position.
Every refusal gives a plain-words reason and the fix; the existing publish evals stay green.

## Acceptance
A test per rule (hit and no-hit, AR/EN/mixed); the existing publish evals unchanged; thresholds in config.
