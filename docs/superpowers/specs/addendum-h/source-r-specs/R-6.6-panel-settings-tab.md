# R-6.6 Panel Settings / onboarding tab per client

Phase 6. Owner: Adobe track (panel), executor (`reel profile`, profile schema).

## Source-R behaviour

- A first-run / settings web page in Arabic (RTL), in steps: identity → style → captions → fonts → post-description
  style → colours → endings → summary; a save-and-start button that also starts setup, with a live progress bar.
- The profile holds name, handle, language, endings (follow card, CTA default, sign-off), brand colours (primary,
  accent, background, text), platforms and six preferences.
- Each preference (style, caption grouping, caption presentation, font, writing style, palette) is either **auto**
  (no value) or **fixed** (a value). A one-video override never changes the profile. A versioned profile schema with
  migration and backups.
- The settings server applies a CSP, checks a token on every request, checks Host and Origin, serves fonts only when
  their hash matches, and uses a single-writer lock.
- The copy is short, warm Egyptian Arabic.

## Our version

- A **Settings tab in our panel** (UXP + CEP), per **client** (agency model: many clients per editor), AR/EN, our
  design tokens; no separate web page.
- Steps (ours): client → brand (colours from the client database, fonts from the client's own font files with live
  previews) → captions (the R-4.1 gallery stills on the client's own clip) → looks (R-6.1 stills, auto/fixed) →
  endings (CTA keyword AR/EN, follow card with the client logo, sign-off phrase) → platforms (safe-zone profiles,
  R-4.5) → summary. **Font previews are engine-rendered stills** served by `reel serve` (HarfBuzz/CoreText with the
  client's font file); the UXP panel never loads client font files itself.
- **auto / fixed per preference**, stored in `reel-profile/style.json`; the panel shows **why** auto chose a value
  (the recommender's reason, R-4.6); the learning loop (T4.3) may suggest fixing a value; the editor confirms.
- `reel profile` validates and writes with a backup and the existing writer lock; a migration step for older
  profiles; the profile schema lives in `schemas/` and is shared by panel and engine.
- Security: the existing `reel serve` model (127.0.0.1, per-run token, Host/Origin checks); the engine reads fonts
  from the client folder read-only to render the previews, never copies them out.
- Copy: short Egyptian Arabic in our voice (written fresh; never Source-R's microcopy).

## Acceptance
A new client is configured without chat; the profile validates against the shared schema; a one-reel override leaves
the profile unchanged; the doctor proof render (R-7.1) shows the client's brand.
