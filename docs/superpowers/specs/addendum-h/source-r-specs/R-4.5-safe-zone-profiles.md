# R-4.5 Platform safe-zone profiles (IG organic, IG ads, TikTok, Shorts, 4:5) + face keep-out data

Phase 4, Task 27. Owner: looks track (`lib/safe_zones*.py`, `config/defaults/safe-zones.json`). QC hooks
(`qc.py`, `motion_readback.py`) and replacing `previews.SAFE_TOP_PX` go through the executor.

## Source-R behaviour

- One platform spec file for Instagram Reels only, at 1080×1920: an organic profile (top and bottom UI bands, side
  margins, and a right-hand action rail in the lower part of the frame), an ads profile (taller bottom band) and an
  ads-with-disclaimer profile (taller still).
- Every number carries a source URL and a basis: "official" (from the platform's pages) or "community" (observed).
- The same file holds delivery encode rules (a closed GOP of a few seconds, an H.264 profile and level) and loudness
  targets (integrated loudness and true peak).
- A delivery gate refuses a render when a graphic sits in a UI area.

Source-R's numbers are not recorded here; ours come from the platforms' own pages and templates.

## Our version

### Data: `config/defaults/safe-zones.json`
```json
{"format": 1,
 "profiles": {
  "ig_reels_organic": {"frame": [1080, 1920],
    "zones": [{"name": "top_ui", "rect": [0, 0, 1080, 0], "basis": "official|template|screenshot|community",
               "source": "<url>", "retrieved": "YYYY-MM-DD", "note": "…"}],
    "caption_band": [x0, y0, x1, y1], "safe_text": [x0, y0, x1, y1],
    "encode": {"codec": "<from source>", "profile": "<from source>", "level_max": "<from source>",
               "gop_s": "<from source>", "closed_gop": "<from source>", "pix_fmt": "<from source>",
               "audio": "<from source>", "loudness_lufs": "<from source>", "true_peak_dbtp": "<from source>",
               "basis": "official", "source": "<url of the platform document>", "retrieved": "YYYY-MM-DD"}},
```
Every `encode` value is filled **only from a cited platform document** (its URL in `source`); a value the platform does
not publish stays absent (no check), never a guess.
```json
  "ig_reels_ads": {…}, "ig_reels_ads_disclaimer": {…}, "tiktok": {…}, "yt_shorts": {…}, "feed_4x5": {…}},
 "default": "ig_reels_organic"}
```
- Every zone number has `basis`, `source` (the platform's own help/ads/creative page) and `retrieved` (date). A
  number without a source is refused by the loader's test. Basis order: `official` (a number on the platform's own
  help/ads page) → `template` (the platform's own downloadable safe-zone template or overlay, measured by us) →
  `screenshot` (only if neither exists: a current in-app screenshot **taken by Yunus on his phone and account**, a
  Yunus step we ask for by name; we measure it and keep it as evidence outside the plugin) → `community` (last
  resort, flagged in the file and in the QC line).
- `safe_text` is the rectangle all text must stay inside; `zones` are the UI rectangles (top bar, bottom caption/CTA
  area, action rail, ad disclaimer); `caption_band` is where our captions sit by default.
- Profiles scale to other frame sizes proportionally (e.g. 720×1280) with rounding toward safety.
- Numbers are re-verified at each minor release (a dated note in the file); platforms change their UI.

### Engine: `safe_zones.py`
- `load(profile=None) -> Profile` (reel override > client profile default > file default).
- `violations(boxes, profile, *, face=None) -> list` — every graphic/text box (from the plan or from the AE/Premiere
  read-back) tested against each UI zone and against the head envelope (R-6.4) when given; returns plain-words
  findings (`"العنوان داخل منطقة أزرار تيك توك على اليمين"`) with the overlap in px.
- `safe_width(profile, side_margin_px)` for caption fit-or-fail (R-4.1).
- Replaces the hard-coded `SAFE_TOP_PX = 220` and the `subtitle-style.json` `safe_area` defaults (both kept as a
  fallback when the file is unreadable, G10).

### Delivery-encode check (part of the same profile)
Each profile also carries its platform's **delivery encode rules** (the `encode` block above, each number with its
source): codec/profile/level, GOP length and closed GOP, pixel format, audio format, integrated loudness and true
peak. `safe_zones.encode_findings(media_info, profile)` compares an exported file with them and returns plain-words
findings («الصوت أعلى من المطلوب لإنستجرام بـ ٢ ديسيبل»). The probes (FFmpeg / ffprobe, no decode where possible):
codec, profile, level and pixel format from `ffprobe -show_streams`; GOP length from the keyframe timestamps of
`ffprobe -show_packets` (K flags); **closed GOP** from FFmpeg's `trace_headers` bitstream filter on a stream copy
(every keyframe must be an IDR NAL unit, type 5 for H.264); loudness and true peak from an `ebur128` pass. It runs in
the R-6.5 export gate and in `reel verify`; a mismatch is advisory in the NLE. Before it can block the handoff package
the editor gets two ways out: `reel verify --fix-encode` writes a conforming **new version** (closed GOP, the
profile's codec/level, loudness normalised; NVENC or x264 by measurement; the original kept), or **accept with a
reason** (recorded with name and time, like R-6.4's accept-overlap; an accepted mismatch no longer blocks).

### QC
`qc.py` and `motion_readback.compare` flag a graphic in a platform UI zone (P1 for text, P2 for decorative shapes
under 20 % overlap), using the reel's selected profile; a multi-platform reel is checked against the union of its
target profiles.

### Better than Source-R
Five platforms instead of one; per-client and per-reel choice; union checks for multi-platform delivery; scaling to
other frame sizes; captions and graphics both use it; the face is a keep-out zone in the same check.

## Acceptance
A test per profile (loader, scaling, every number has source + date + basis, the encode block present);
`encode_findings` flags a seeded open-GOP / wrong-level / too-loud fixture and passes a correct one; QC flags a seeded graphic in each profile's
rail/bottom zone; a box outside all zones passes; an unreadable file falls back without an error.
