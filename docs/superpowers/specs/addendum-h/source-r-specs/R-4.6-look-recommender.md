# R-4.6 Look recommender: content type + client reference + recent-use penalty, with a plain reason

Phase 4, Task 28 (caption looks now; motion looks in Phase 6). Owner: looks track (`lib/looks*.py`). The `plan.py`
flag and the panel display go through the executor / Adobe.

## Source-R behaviour

- Each style has fit scores per **purpose** (explainer, tutorial, comparison, story, opinion, case study, …) and per
  **tone**, and a list of semantic scene families that earn a bonus when the brief uses them.
- Score = purpose fit + tone fit + semantic bonus − a repetition penalty for recently used styles (the most recent
  use costs the most, decreasing with age, never below a floor).
- An explicit or fixed style always wins. Ties break by the registry order.
- The pick and any notice are relayed to the creator in one line.

## Our version

### Inputs
- **Content type** from our pipeline (story-editor / episode-analyst): `storytelling`, `drama`, `success_story`,
  `advice`, `bold_opinion`, `emotional`, `comedy` (the recipe types in `motion-beats.md`), plus `explainer`,
  `list`, `medical_claim`, `interview` (podcast). It is read from the reel's `00_inputs/source.json` (`content_type`,
  else the recipe's `type`, written by `reels-select`). An ordinary edit clip has none, and neither does an unknown
  (profile-added) type: its fit counts as neutral (0.5) for every look and the reason line names no type.
- **Client reference style**, only from fields that exist and are measured: `ref_analysis` gives `cuts_per_minute`
  per reference video; the client's `editing-style.json` (free-form, written by client-researcher) is used only for
  the optional keys `caption_density` (`low|medium|high`) and `text_weight` (`light|regular|heavy`) when present.
  Missing keys contribute nothing (no guessing).
- **Client history**: the looks of the client's last 10 reels that recorded one, newest first by **when each look was
  recorded**: each reel's `01_analysis/look-choice.json` (`record_choice(paths, kind, look, source)`, written when a
  look resolves, `at` to the microsecond with its time zone, nudged just past the client's newest recorded `at` so
  one Windows clock tick keeps the order; `source` editor marks a hand swap for the learning loop, and a swap re-dates
  its reel: it is the newest choice). Reels picked at Gate 0 share one `created` second, so the order they were built in is what counts. A choice
  with no valid `at` (older files) is dated by its project-status `created`; times are compared in UTC (a time with
  no zone is local). Re-recommending a reel that already recorded its own look counts only the choices recorded up to
  it. A missing or garbled file, a choice with no valid time, and this reel itself (any letter case) count as no look.
- **Speech rate** (words per second) for caption grouping.
- **Preference**: the reel-profile `auto|fixed` value; a reel override (edit-decisions `global.caption_look` /
  `global.motion_look`). Caption: grouping **and** presentation fixed → that look, no scoring; only one of them fixed
  → only the looks that match it are scored.

### Score (deterministic)
All tables live in `config/defaults/looks/recommender.json` (the **only** home of fit tables and look traits; look
files carry none).
```
score(look) = 3·fit[content_type][look]            (0..1)
            + 2·ref_match(look)                    (0..1, below)
            + 1·delivery_fit(look, speech_rate)    (0..1; caption looks only, motion looks get 0.5)
            − recent_penalty(look)                 (motion looks only; Σ over the client's last 10 reels that used a
                                                    motion look: 0.8 · 0.6^age; ordinary clips do not count)
```
- `ref_match`: the look's `energy` trait (0..1) vs the client's energy `clamp((median cuts_per_minute − 6) / 24, 0, 1)`
  → `1 − |difference|`; plus, when the optional keys exist, `caption_density` and `text_weight` matches (1 / 0.5 / 0)
  averaged in. With no reference videos at all, `ref_match = 0.5` for every look (neutral).
- **Hard variety rule (motion looks only)**: if the top motion look was also used in **both** of the client's last two
  reels that used a motion look, the next-ranked motion look is picked instead (unless the look is fixed or overridden); if there is no next
  look, or its `fit` is below 0.3, the result is "no look" (the fallback below). This, not the penalty alone,
  guarantees no motion look three times in a row.
- **Caption looks keep the brand consistent**: there is no variety rule and no recent-use penalty for caption looks;
  under "auto" the same content type and speech rate give the same caption look every time.
- `fixed` or a reel override → that look, no scoring (the reason line says so).
- Ties: the higher `fit`, then the catalog order in `recommender.json` (stable).
- **Motion looks in `preview_gate`** (R-6.1) are never auto-picked. If no motion look is `accepted` yet, or none has
  `fit ≥ 0.3` for the content type, the recommender returns **no look**: the build uses today's recipe theme and
  scenes unchanged, and the editor sees one line («لسه مفيش شكل جديد اتراجع واتعتمد للنوع ده، فاستخدمنا الشكل
  الأساسي.»). The motion catalogue is `config/defaults/looks/motion/*.json` (`name`, `display`, `status`); it is empty
  until Phase 6 builds the first look, so today every motion recommendation is "no look".
  The editor can still pick any **built** look by hand (`preview_gate` or `accepted`); `planned` looks are never
  listed (R-6.1), and a playful look is not listed on medical or religious content. An unknown or planned reel
  override (caption or motion), or an invalid grouping/presentation value in a caption override, gets the plain
  note «الشكل «…» مش جاهز للاستخدام، فاخترنا غيره.» and the look is scored as usual.
- **Caption looks** have no preview gate in the recommender: all 8 are accepted together at Task 23's gallery
  distinctiveness review, before Task 23 completes.
- Medical/religious content never gets a look whose `playful` flag is true, not even by a reel override (refused
  with a plain note); a profile that cannot be read counts as religious (the safe side). Only looks with `fit ≥ 0.3`
  take part in the ranking, so a low-fit look never blocks one that fits.
- A client's own caption look or a profile's content type that the tables do not cover scores neutral for the
  missing values (fit, traits, and the delivery fit of a grouping the delivery table does not name), with a
  warning.

### Output
`looks.recommend(paths, kind="caption"|"motion") -> {"pick", "top": [3 looks with score + one still each],
"reason": "…"}`. The reason is **one plain line** in the editor's language, no internal terms, e.g.
«اخترنا شكل الكابشن «phrase-boxed» عشان نوع الفيديو نصايح بخطوات والكلام سريع.» (caption look: content type and
speech rate only); «اخترنا الشكل «…» عشان نوع الفيديو …، وغيّرنا عن الشكل اللي اتكرر في آخر فيديوهين للعميل.» (motion
look: may cite the client's recent reels). The wording was reviewed by the short-video editing coach (2026-10-17); all
lines live in `recommender.json` `reason.ar` / `reason.en`.
One click (panel) or `--look <name>` swaps it; the swap is recorded for the learning loop.

### Better than Source-R
Our content types come from meaning analysis, not a hand-written purpose tag; the client's own reference style is a
signal; the variety penalty is per client (agency model); medical/religious safety; top-3 with stills; plain reasons.

## Acceptance
Deterministic tests per content type (same input → same pick); five reels in a row of the same content type for one
client never give the same motion look three times in a row (the hard variety rule), unless fixed, while the caption
look stays the same under "auto"; with no accepted motion
look the result is "no look" with the plain line; an explicit look always wins; the reason line has
no internal terms (a word list test: no "score", "vector", "penalty", "cosine", "fit["); it names the look by its
display name (the working code until Yunus approves names).
