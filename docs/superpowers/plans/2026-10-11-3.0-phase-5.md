# WhyNot Cut 3.0 — Phase 5: Magnific MCP integration

Spec: master plan §7 Phase 5 (T5.1–T5.9), decision D6. Evidence: `docs/review/2026-10-11/magnific-brand.md` Part 1
(tool list §1.2, licensing §1.4, bundling/dedupe §1.5, the 12 usage rules §1.6), master plan Appendix F (manifest
record).

## Global Constraints (bind every task)

- Repo root `WhyNotCut/`; plugin `whynot-cut/`; branch `release/3.0`; one commit per task (conventional message ending
  with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`). Tests `bash tools/test.sh` (engine runtime). TDD.
- **Zero automatic spend.** A spending Magnific tool runs only for an approved line item (tool + need id) within the
  remaining approved budget; everything else → `ask` (or `deny` for the deny list). Absence of Magnific never blocks
  the pipeline: needs are listed as "material not sourced" with anchors.
- Tool-name prefixes to handle everywhere (code, hooks, agents): `mcp__magnific__`, `mcp__plugin_whynot-cut_magnific__`,
  `mcp__claude_ai_Magnific__`.
- Spending tools: `images_generate`, `images_generate_svg`, `images_to_svg`, `images_upscale`, `images_crop`,
  `images_remove_background`, `video_generate`, `audio_tts`, `models3d_generate`, `custom_references_create`,
  `creations_request_upload`, `creations_upload`, `creations_finalize_upload`, `folders_delete`. Read-only:
  `account_balance`, `project_report`, `creations_search|get|show|wait`, `creation_status`, `*_models_list|show`,
  `audio_voices_list|show`, `custom_references_list`, `folders_list|get`, `spaces_list|view`, `tools_show`.
- Never faces or real people; never generate text inside images; never Quran/hadith calligraphy; medical/religious
  assets pass medical-reviewer before placement.
- Client `assets/` and `data/` stay read-only: all Magnific files, approvals and manifests live under `output/`.
- Licence: never deliver editable files containing Magnific assets to clients (`transferable_to_client: false`).
- Default budget per reel: userConfig `magnific_budget_credits` (default 300).

### Task 2: T5.2 Agent and knowledge

mcp__plugin_whynot-cut_magnific`; `skills: asset-craft`; colour per valid list; description ≤ budget style). New skill

asset-scout with approval". Every other agent keeps `disallowedTools` for Magnific (T3.3).
- **Acceptance:** structure tests (budget, valid frontmatter, skills exist); validate --strict.

### Task 3: T5.3 Needs in the plan

`asset_needs[]` in `edit-decisions.json` and `motion-script.json` (schema from T2.3): `id`, `purpose`, `kind`
(upscale | vectorize | cutout | icon | background | broll_still | broll_video), `anchor {segment, start, end, phrase}`,
`topic`, `constraints`, `max_credits`. `reel plan` / `motion-plan` reject anchors whose phrase is not in the transcript
at that time window (normalised Arabic match); compiled artefacts carry the needs. story-editor / motion-director
author needs (skill + agent text); graphic-checker scores relevance 0–2 (text).
- **Acceptance:** tests: valid anchor accepted; phrase not in window → plan error; unknown kind → error.

### Task 4: T5.4 Engine commands

`reel assets-plan` (needs + estimates + what local sources already satisfy: client database assets, previous manifest
entries/caches); `reel assets-approve --by editor [--allow-video] [--budget N] [--ids N01,N02]` (editor-only; guard
blocks subagents) → `output/projects/<ID>/05_assets/assets-approval.json` with line items and budget;
`reel assets-ingest --creation <id> --url <url> --need <id> [--tool ... --model ... --prompt ... --credits-before N
--credits-after N]` downloads into `output/projects/<ID>/05_assets/magnific/`, sha256, writes/updates
`05_assets/magnific-manifest.json` (Appendix F fields, `transferable_to_client: false`), caches into
`output/client_database/magnific-cache/` (client assets) or `${CLAUDE_PLUGIN_DATA}/magnific-cache/` (generic icons /
backgrounds; fall back to `~/.whynot-cut/magnific-cache/` when the var is unset); `reel assets-manifest` shows them.
Downloads: https only, size cap, content-type check, no redirects to non-https.
- **Acceptance:** unit tests with a local HTTP server fixture (or file:// injected downloader) for ingest; approval
  record; manifest schema.

### Task 5: T5.5 Spend guard

PreToolUse hook `hooks/magnific_guard.py` (stdlib only, via run_python.sh) registered in hooks.json with a matcher
covering the spend tools for all three prefixes. Read-only tools pass. Spend tools allowed only when an approved line
item matches (tool + need id given in the tool input or the most recent `assets-plan` mapping) and the remaining budget
covers the estimate; otherwise `permissionDecision: "ask"` with a reason. Deny: `custom_references_create` on persons
(any), `folders_delete`, `audio_tts` (client content), `video_generate` unless approval has `allow_video: true`,
`creations_upload`/`creations_request_upload` of footage, audio or anything outside `output/client_database/assets/`.
Every call logged to `output/projects/<ID>/logs/magnific.log` (resolve the project from cwd/approval files; if none,
`~/.whynot-cut/logs/magnific.log`). The asset-scout records `account_balance` before/after each batch (skill text +
`assets-ingest` fields).
- **Acceptance:** hook tests (stdin JSON → stdout JSON/exit code) for each allow/ask/deny branch and all 3 prefixes;
  latency < 200 ms.

### Task 6: T5.6 Optional REST stock + SFX [P1]

If `magnific_api_key` is set (userConfig sensitive → env `CLAUDE_PLUGIN_OPTION_MAGNIFIC_API_KEY` or keychain-backed
value as Claude Code exposes it; check docs), `reel stock-search --term … --kind video|photo|icon --orientation vertical
--people exclude` (header `x-magnific-api-key`, `Accept-Language` for Arabic terms) and `reel stock-download --id …`
(saves the licence PDF path into the manifest, `license_type: stock-premium`); `reel sfx-generate` (REST sound-effects,
async task polling) as an alternative to local synthesis. Without a key: commands return `{"blocked": "...", "how":
"set magnific_api_key in /plugin config"}` and the pipeline continues.
- **Acceptance:** unit tests with a fake HTTP server; no-key path test. Never log the key.

- **Acceptance:** tests per placement path.
