## Task 1: Contract v4 — schemas, protocol constant, vendored validator

Files (new): `whynot-cut/engine/reel/contract/__init__.py`, `validator.py`, `protocol.json`, `request.schema.json`,
`result.schema.json`, `progress.schema.json`, one `<action>.schema.json` per action; test file
`whynot-cut/tests/test_contract.py`.

- `protocol.json`: `{"protocol": 4, "actions": {...}}` mapping each v4 action to `{host: "premiere"|"aftereffects"|"engine"|"any",
  cep: "<current NHPP/NHAE action name or null>", uxp: true|false}`. Actions (13 from the spec + 2 AE helpers the engine
  already calls): `ping`, `status`, `probe`, `build_project`, `export_frames`, `close_project_path`, `clip_components`,
  `open_project`, `set_player_position`, `render_review`, `ae_build_motion` (CEP `build_motion`), `ae_readback` (CEP
  `readback`), `ae_render` (engine-side aerender, no CEP action), `ae_fonts` (CEP `fonts`), `ae_probe_text` (CEP
  `probe_text`).
- Each action schema has `$defs.data` (request data) and `$defs.readback` (result readback). Derive them by READING:
  `whynot-cut/templates/premiere/nh_ppro_lib.jsx` (`NHPP.actions.*`), `whynot-cut/templates/after_effects/nh_ae_bridge.jsx`
  (`NHAE.actions.*`), `lib/ppro_build.py` (`job_data`, `build` checks, `export_frames`), `lib/motion_build.py`
  (`job_data`, `preconditions`, `build`), `lib/motion_readback.py` (`compare` reads), `lib/ae_render.py`
  (`aerender_cmd`/`render`), `lib/ae_probe.py`. Rules: every field the engine READS from a readback is `required` with
  its type; every field the engine SENDS is described; open dumps (Premiere `getSettings()`) allow additional properties;
  request `data` objects are closed (`additionalProperties: false`) except where the engine passes through open plan
  objects (e.g. AE `job`). New UXP-only actions (`status`, `open_project`, `set_player_position`, `render_review`) get
  minimal shapes (documented in a `description`): status → `{host, hostVersion, bundle, protocol, busy, project}`;
  open_project `{path}` → `{opened, project}`; set_player_position `{sequence_name, t_s}` → `{position_s}`;
  render_review `{sequence_name, out_path, preset_path?}` → `{started, out_path, mode}`.
- `ping.readback` covers both hosts (`anyOf` Premiere `{version, build, project, projects_open}` / AE ping fields).
- `request.schema.json`: `{protocol: const 4, id: string 1..64 [A-Za-z0-9._-], action: enum(actions), data: object,
  expires_at: ISO date-time string}`, all required, closed. `result.schema.json`: `{ok: bool, action, readback: object,
  error?: string, how?: string, id?: string}`; `readback` required when ok is true. `progress.schema.json`:
  `{event: const "progress", id, action, step: string, n?: int ≥0, of?: int ≥1, elapsed_s?: number}`.
- `validator.py`: a draft-2020-12 SUBSET validator, stdlib only. Supported keywords: `$ref` (local `#/$defs/...` and
  `<file>.schema.json#/$defs/...` within the contract folder), `$defs`, `type` (incl. list, "integer" excludes bool),
  `properties`, `required`, `additionalProperties` (bool or schema), `items`, `minItems`, `maxItems`, `enum`, `const`,
  `minimum`, `maximum`, `minLength`, `maxLength`, `pattern`, `anyOf`, `oneOf`, `format` (`date-time` only), plus the
  annotation keywords `$schema`, `$id`, `title`, `description`, `examples`, `default`. Any other keyword in a contract
  schema is an error (`check_schema`). API: `validate(instance, schema_or_name) -> list[str]` (errors with JSON
  pointer paths, empty = valid); `load(name)`; `check_schema(schema) -> list[str]`; `validate_request(req)` /
  `validate_result(res)` that also validate `data`/`readback` against the action's `$defs`.
- `__init__.py` exports `PROTOCOL = 4`, `ACTIONS`, `CONTRACT_DIR`, and the validator API. Import path inside tests:
  same pattern the other tests use (`sys.path` to `whynot-cut/engine/reel`, `from contract import ...` or the existing
  convention — check `test_motion.py`).
- Tests (TDD, in `test_contract.py`): every schema passes `check_schema`, is valid JSON, has the right `$schema`/`$id`;
  `protocol.json` lists exactly the schema files; validator unit tests per keyword (positive + negative, bool vs integer,
  `$ref` across files, error paths); request/result envelope positive + negative cases (wrong protocol, unknown action,
  missing readback on ok, expired format). If the `jsonschema` package is importable, additionally validate every
  schema with `Draft202012Validator.check_schema` (skip otherwise).

## Task 2: Golden fixtures, CEP→v4 adapter, engine-request tests

Files (new): `whynot-cut/tests/fixtures/contract/<action>/{request.json,result.json,…}`, `whynot-cut/tests/fixtures/contract/README.md`,

- Source of truth: recorded CEP job pairs in `~/.whynot-cut/ppro-queue/*.data.json` + `*.result.json` and
  `~/.whynot-cut/ae-queue/…` (Premiere 26.5.2 / AE 26.5, bridge 3.1.0), and
  `../whynot-test/**/07_premiere/ppro-build-result.json`, `../whynot-test/**/04_after_effects/motion-build-result.json`.
  Pick for each CEP action the most recent SUCCESSFUL pair from a PODCAST-TEST (or بودكاست-تجربة) project; anonymise any
  other path to the PODCAST-TEST layout; never copy a real client name. Large arrays may be trimmed to ≤ 5 items with a
  `"_trimmed_from": N` note in the fixture README (not inside the JSON). Keep the raw CEP pair as
  `cep-data.json`/`cep-result.json` and the v4 envelopes as `request.json`/`result.json`. Actions with no recording

  get fixtures written from the code's shapes, marked `"recorded": false` in `fixtures/contract/index.json`
  (`{action: {recorded: bool, source: "<queue file or path, anonymised>", host_version}}`). Live re-record is T6.9.
- `cep.py`: `to_request(action_v4, data, *, id, expires_at)` builds a v4 request; `from_cep(action_v4, cep_response)`
  maps the queue's parsed response `{ok, action, result}` / error `{ok:false, error, line}` to a v4 result
  `{ok, action, readback, error?, how?}`; `CEP_NAME[action_v4]` from `protocol.json`. Pure functions, no I/O.
- Tests: every fixture `request.json`/`result.json` validates; every `cep-result.json` converted by `from_cep` validates
  and equals `result.json`; negative mutations of each golden readback (drop a required key the engine reads, wrong type)
  are rejected; **engine requests validate**: run the engine's own request builders with the bridge mocked and validate
  each captured `(action, data)` with `validate(data, "<action>#/$defs/data")` — at least `motion_build.build` (reuse the
  `test_motion.py` reel fixture pattern that mocks `ae_bridge.submit`) and `ppro_build.build`/`export_frames` (mock
  `ppro_bridge.submit`/`status`; reuse `test_pipeline.make_project` or the `test_plugin.py` pattern). If a builder cannot
  run in a unit test, validate its recorded request fixture instead and say so in the report. Do not modify engine
