# WhyNot Cut 3.0 — Arabic guide, round 2 (reader QC + Addenda A–D) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The draft guide reads clearly for a first-time Egyptian editor, and it covers the 3.0 additions: the three
editor tools (Tidy, Hush, Kalam) and their combined flow, the website-look AR/EN panel, one ecosystem, and the
zero-effort install.

**Architecture:** Same pipeline as round 1 (`guide-ar/`, `build.py`, lint, two-pass TOC, `--release`). Chapters are
renumbered to a 19-chapter outline (three tool chapters inserted after «التعديلات»). New and rewritten chapters
describe the 3.0 behaviour that the binding specs fix, in the present tense, and every such section carries a `.todo`
box naming the phase that verifies it live; undecided items (spikes, H-items) appear only inside `.todo` boxes.

**Tech Stack:** HTML/CSS, Python 3.12 (engine venv: pypdf, fontTools), Edge headless, pypdfium2 (scratch QC venv).

**Spec:** master plan `docs/superpowers/specs/2026-10-11-whynot-cut-3.0-master-plan.md` (Phase 10, Appendix E);
`docs/superpowers/specs/addendum-a/ADDENDUM-A-kalam-hush-tidy.md` + `addendum-a/prd/{tidy,hush,kalam}-prd.md`;
`addendum-b/ADDENDUM-B-ui-ux-website-look.md`; `addendum-c/ADDENDUM-C-one-ecosystem.md` (+ `evidence/ecosystem.md`);
`addendum-d/ADDENDUM-D-zero-effort-install.md`. Round-1 plan: `2026-10-11-3.0-phase-10-guide-track.md`.

## Global Constraints

- Everything in the round-1 plan's Global Constraints still binds (paths, RTL, bdi, Western digits, palette, fonts,
  white logo only, header/footer, fictional `example-clinic` only, gender never guessed, Arabic with Write/Edit only).
- Owner decisions since round 1: product line «WhyNot Cut · Powered by thewhynot.ai» (never "Powered by Claude");
  tool names **WhyNot Tidy / WhyNot Hush / WhyNot Kalam**, Arabic UI «تايدي» «هَش» «كلام» (Addendum A6b); "Hoka"
  never appears.
- Arabic style/terms: `guide-ar/STYLE.md` (moved into the repo in Task 1 from the round-1 workspace file). Where the
  panel already has an Arabic string for the same thing (`adobe/panel-ui/i18n/ar.json`), the guide uses the panel's
  wording, so screenshots and text match.
- Commits: private index built from the CURRENT HEAD right before committing (COORDINATION rules 9–11); only own
  paths (`guide-ar/**`, `whynot-cut/docs/WhyNot-Cut-Guide-AR.pdf`, this plan); after committing, `git show --stat
  HEAD` lists only those; no push. Focused tests only (`guide-ar/tests`), never the shared full suite.
- Truth rule (ruling R2-1): behaviour fixed by a binding spec may be written in the present tense as the 3.0 product
  **only** inside a section that carries a `.todo data-phase="N"` box naming the phase that verifies it live. Today's
  verified behaviour needs no box. Undecided items (spike results, H-items like H4 signing, H14 subscription jobs)
  are described only inside `.todo` boxes. Nothing is invented beyond the specs.
- Commands: never write a `reel …` command that `reel --help` does not list (test `test_reel_commands_exist`). Planned
  commands (`reel kalam`, `reel models`, …) are named only in plain words, not as `<code>reel …</code>`. The guide
  prefers what the editor SAYS to Claude and what they click in the panel (Addendum C: no commands on screen).

## Review Focus

1. A chapter renumber leaves a stale link (`href="#ch11-…"` pointing at the wrong chapter) → Task 1 test
   `test_chapter_numbers_match_files` (h1 number = file prefix) + the existing broken-anchor lint.
2. Present-tense 3.0 text without a `.todo` box in its section → Task 7 checker script `check_truth_boxes` (each
   chapter in a list of "3.0 chapters" must have ≥1 `.todo` per h2 that is not marked `data-today`) — a lint rule
   under `--release` is not needed (todos fail release anyway).
3. Terms differ between guide and panel (e.g. «محتاجك» vs a panel string) → Task 5 compares every panel label the
   guide quotes against `adobe/panel-ui/i18n/ar.json`.
4. A first-time reader stops at jargon (Gate, profile, recipe, fps) → Task 2 reader review + Task 3 fixes.
5. Tool chapters drift from the PRDs (renamed controls, dropped safety rule) → Task 6 fact-check against each PRD's
   §5 flow and §8 safety rules.
