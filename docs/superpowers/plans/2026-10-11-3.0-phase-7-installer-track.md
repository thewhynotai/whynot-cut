# WhyNot Cut 3.0 — Phase 7 installer track (T7.1, T7.2, T7.3, T7.8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A per-user, admin-free, idempotent, resumable installer (PowerShell for Windows, bash for macOS) that takes an
editor from "Claude desktop installed" to "WhyNot Cut ready", plus its uninstall, fully testable against temp homes.

**Architecture:** Two thin shell bootstraps (`core/bootstrap.ps1`, `core/bootstrap.sh`) do only what needs no Python:
read the uv pin from `setup/components.json`, download + sha256-verify uv, `uv python install` the pinned
python-build-standalone 3.12, then hand over to ONE stdlib-only Python core (`core/wnc_install.py` + package
`core/wnc_installer/`) that runs every remaining step identically on both OSs. Front ends `installer/install.ps1` /
`install.sh` locate (or, in one-liner mode, fetch) the plugin and call the bootstrap. A `--home <dir>` sandbox mode
redirects HOME/USERPROFILE/APPDATA/LOCALAPPDATA/CLAUDE_CONFIG_DIR and replaces every machine-global side effect
(registry, font broadcast, app launch, PATH lookups, UPIA) with recorded no-ops, so tests never touch this PC.

**Tech Stack:** Python 3.12 stdlib (core), Windows PowerShell 5.1 (no `&&`, no `??`), bash 3.2-compatible (macOS
default bash), uv, python-build-standalone, unittest.

**Spec:** `docs/superpowers/specs/2026-10-11-whynot-cut-3.0-master-plan.md` (§4 D7 D8 D14 D15 D17, §5.1, §5.3, §5.4,
§6, §7 T2.1 + Phase 7) and `docs/review/2026-10-11/installer.md` (R.1–R.8). Read both before any task.

## Global Constraints

- Paths relative to `WhyNotCut/whynot-cut/` unless they start with `WhyNotCut/`. Branch `release/3.0`, one commit per
  task, commit ONLY this track's paths (`git status --short` first; `git commit -m "…" -- <paths>`; never stage
  `PROGRESS.md`; retry on `index.lock`). Message: conventional, ends with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No tags.
- Never touch: `engine/`, `hooks/`, `skills/`, `agents/`, `bin/`, `setup/setup_env.py`, `setup/locks/`, `PROGRESS.md`,
  `tests/test_plugin.py`. Requests for those go to the executor via the STATUS note.
- **Never run the installer for real** against this PC's `~/.whynot-cut`, `~/.claude`, fonts, registry or Adobe
  folders. Every test uses `--home <tempdir>`. Never delete anything outside temp dirs. Never write into
  `D:\WhyNot Clients`. Never set Adobe PlayerDebugMode (no code path writes `CSXS.*`).
- No admin: no HKLM writes, no Program Files writes, no UAC; registry only `HKCU\…\Fonts` (and only outside sandbox).
- Engine home layout (installer.md R.1): `~/.whynot-cut/{bin/uv(.exe), python/, runtimes/<id>/, current, ffmpeg/<ver>/,
  cuda/bin/, models/, bridge/, state.json, logs/install-*.log, cache/uv/, downloads/, fonts/<ver>/, marketplace/}`.
- **Runtime contract (shared with the executor's T2.1):** `current` = UTF-8 text, one line `<runtime-id>`, written
  atomically (tmp + replace), switched only after the smoke import passes; the previous runtime is kept.
  `runtimes/<id>/` = a venv made by `uv venv --python <pbs 3.12>` (no system/user site); interpreter
  `Scripts/python.exe` (Windows) or `bin/python` (POSIX). Stamps: `runtimes/<id>/WHYNOT_RUNTIME` (JSON `{id, platform,
  python, lock_file, lock_sha256, created_at, by}`) and `runtimes/<id>/.whynot-lock.sha256` (hex). Runtime id =
  `components.runtime.locks.<plat>.id`, or when that is a placeholder `"r-" + sha256(lock bytes)[:12]`. Lock =
  `setup/locks/runtime-<plat>.lock` (`uv pip compile --generate-hashes` format) installed with
  `uv pip sync --require-hashes --python <runtime python> <lock>`. Platforms: `win-x64`, `mac-arm64`, `mac-x64`.
- Placeholder convention in `components.json`: the string `"<release>"` (or `null`) = filled by the release tool later.
  The installer treats it as "not available in this build": the step is `skipped` with a reason, never guessed.
- Every download: pinned URL + sha256 verified before use; mismatch → file deleted, step `red`. Downloader: `curl`
  (present on macOS and Windows 10+) with `urllib` fallback; cache in `~/.whynot-cut/downloads/`.
- Engine calls from the core use the runtime directly: `<runtime python> -s -B <plugin>/engine/reel/cli.py <cmd>` with
  `WHYNOT_HOME=<engine home>`, `PYTHONUTF8=1`.
- Settings files: `~/.claude/settings.json` (or `$CLAUDE_CONFIG_DIR/settings.json`) is merged, never overwritten:
  timestamped backup `settings.json.whynot-backup-YYYYmmdd-HHMMSS` only when something changes; unreadable JSON → no
  write, step `amber` with the snippet for the editor. Managed settings are never touched.
- Tests: `whynot-cut/tests/test_installer.py` only (+ fixtures under `tests/fixtures/installer/`); run
  `bash tools/test.sh -p test_installer.py` (engine runtime, `-W error::ResourceWarning`: close every server, file and
  process). `sys.dont_write_bytecode = True` at the top; helper runs use `python -B`. No real network: artefacts are
  served by a `http.server` on 127.0.0.1 started in the test (or `file://`). Skip cleanly (`skipTest`) when
  `powershell`/`bash` is missing.
- Write files containing Arabic with the Write/Edit tools, not shell heredocs.

## Decisions taken for this track (logged; the executor copies them into PROGRESS.md)

- **ID-1 One Python core, thin shells.** The spec asks for "PowerShell + bash, the same steps". Only uv + Python
  bootstrap is shell; every later step runs in one stdlib-only Python core on the freshly installed python-build-
  standalone. Why: identical steps on both OSs by construction, unit-testable, and it avoids PowerShell 5.1's
  `ConvertTo-Json` quirks and bash's lack of JSON for the `settings.json` merge.
- **ID-2 Fonts are downloaded, not vendored**: pinned google/fonts commit + sha256 in `components.json`, OFL texts
  fetched alongside. Keeps the plugin archive small; the release tool can later point them at the owner's CDN pack.
- **ID-3 No exec bit on the installer `.sh` files**: they are always run as `bash installer/install.sh` or `curl | bash`,
  so `package.py` `EXEC` and the git-index test stay untouched.
- **ID-4 Language default `ar`** in the installer question (audience: Arabic-speaking editors); an existing preference
  wins.
- **ID-5 `reel-editor@*` (the 1.x product name) is disabled** in `enabledPlugins` when it is on: it would put a second
  `reel` on PATH. Reversible, backed up, logged.
- **ID-6 Questions are asked right after preflight** (not at step 9) so the long downloads run unattended; their answers
  are written by `reel settings --init` once the runtime exists.
- **ID-7 Until H3 the marketplace is the managed directory `~/.whynot-cut/marketplace`** (refreshed from the zip the
  installer runs from); once `marketplace.url` is pinned, the same step migrates to the URL source with `autoUpdate`.

## Review Focus

1. **An existing `settings.json` with a BOM, unusual keys, or invalid JSON** — expected: BOM read fine and kept keys
   intact; invalid JSON is left byte-identical and the step says what to paste. (Task 3 tests.)
2. **Re-run after an interruption** (partial download in `downloads/`, runtime dir without stamps, `current` naming a
   missing runtime, failed `pip sync`) — expected: resumes, re-verifies, never points `current` at a broken runtime.
   (Task 1 + Task 2 tests.)
3. **Home path with a space and Arabic letters** (`…/محمد علي/`) — expected: every step and both shell bootstraps work.
   (Task 5 tests use such a home.)
4. **Any sha256 mismatch or placeholder pin** — expected: nothing installed from that file, the bad file deleted,
   `red`/`skipped` with a reason, later independent steps still run. (Task 1, 2, 4 tests.)
5. **Uninstall next to client data** (clients folder inside the engine home, a folder with `.whynot-client`, a
   symlink/junction inside `~/.whynot-cut`) — expected: never deleted or followed; models kept unless asked.
   (Task 6 tests.)
