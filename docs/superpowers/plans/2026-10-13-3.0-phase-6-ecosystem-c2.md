- the generated validators, if the schemas they cover change;
- tests: `test_contract.py`, `test_serve_app.py`, a new `test_serve_engine_state.py`, and the TS tests.

Steps:
- **`hello.client.build` (optional string, max 64).**
  - The daemon reads `whynot-cut/adobe/expected.json` (`{product, build, sha}`). release.py writes it, which is the
    executor's part. When the file is absent, `update` is `"unknown"`.
  - The daemon answers `welcome.update = {panel: "ok"|"stale"|"newer"|"unknown"}`. The comparison is by `build`; an
    unparsable value is `"unknown"`.
  - Tests cover each case.
- **Engine-state shape `active.json` (`~/.whynot-cut/state/active.json`).**
  - Shape: `{client_root, item, stage, session_id, claude_pid, at}`. Write it as a schema and document it as written
    by `reel` writer commands, which are the executor's T6.2b.
  - `engine_state.py` reads it, defensively: a missing, oversized (> 64 KiB), invalid or stale file means no item.
    A file is stale when `at` is more than 12 h old. Also read the item's evidence files when they are present and
    valid: `plan.json` → approval card with fingerprint; `plan-approval.json` → approved; `qc-*.json` → QC tiles.
  - Fill `PanelState` from them: `client`, `item`, `pipeline`, `approval`, `qc`. Read only; never write.
  - Exact evidence file names and fields come from the engine's existing writers. Read them, don't invent; cite
    file:line in the code comment. Where a field is unknown, leave it out.
  - Snapshot and state messages use it.
  - Tests use fixture client trees under a temp home, including path traversal in `item`/`client_root` (refused)
    and Arabic paths.
- **Intents final.**
  - `approve{item, fingerprint, editor_name}` stays as it is.
  - `request_changes{item, text, editor_name}` stays as it is.
  - `rebuild{item, replace_edited}`: `project_path` becomes optional. The engine knows the project from the item;
    a panel that sends it keeps working.
  - All three are answered by `reply{ok, how}`.
  - Until T6.2b they keep answering `ok:false`, with an editor-language `error` and a `how` that names no command,
    e.g. "Do this step in your Claude session for now — it will work from the panel after the next update." Fix
    `NOT_YET_HOW`.
  - Add a test that no `reply.how`/`error` string emitted by serve contains `reel ` or a backtick.
- **Claude pill.** Extend `ClaudeState` and the session schema to
  `not_installed|signed_out|plugin_outdated|ready|working|waiting|unknown` (keep `unknown` for "not probed yet").
  - Update the comment in `source.ts`.
  - The daemon reports `unknown` until the T6.2b probe exists; the shape only, no probing this round.
- **Validators.** Regenerate them (`premiere-uxp/scripts/gen-validators.mjs`) and keep the TS/Python equality tests
  green.
