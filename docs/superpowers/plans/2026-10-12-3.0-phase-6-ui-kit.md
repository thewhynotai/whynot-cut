Task 2 notes (2026-10-13, after the live spike 0.1.7 CSS lab in Premiere 26.5.2 UXP; the evidence is in
`docs/adobe/evidence/ui-kit/uxp-lab-017/` and the record in `docs/adobe/uxp-parity.md` "Spike 0.1.7 CSS lab"):
- **Documented deviation from Addendum B: the CTA glow is a shadow, because UXP cannot clip a gradient ring.** Every
  gradient-ring variant failed. With a radius, the wrapper's gradient corners show square, and `border-image` shows
  nothing. The main CTA's glow is therefore one `box-shadow`, `--twn-cta-glow: 0 0 10px rgba(217,92,155,.6)` in
  `brand/tokens.css`. It is a single shadow because a multi-shadow value is unproven in UXP. The gradient stays on the
  header hairline and the progress fill only.
- The kit never emits `<button>`, which UXP paints as Premiere's native grey control. Every control is a
  `<div role="button" tabindex="0">` (`role="tab"` for tabs). Enter and Space activate it (`src/kit/activate.ts`). A
  disabled control has `aria-disabled` + `.kit-btn-disabled` + `tabindex="-1"`. A control's radius is the explicit
  half-height 16 px (`--twn-radius-control`); 999 px stays on `<span>` chips (the Global Constraints' "999 px pills").
- Icons carry no `fill` attribute (UXP paints nothing for it, nor for `currentColor`). A CSS ink class
  (`.kit-ink-*`) fills them.
- `@font-face` loads in no form in UXP, so the panel must look right with system fonts. Each token stack names the
  brand family first, then Windows / macOS fallbacks. `fonts.css` ships for CEP / Chromium only, and no UXP page links
  it. The installer will install the brand fonts for the user.
- Side-by-side flex runs are spaced by `.kit-gap-s`, a physical margin (`margin-inline-*` does nothing in UXP). A
  Latin word inside an Arabic sentence is a `<bdi dir="ltr">` run.

Task 2 notes, B-T1 close-out (2026-10-13, after the live spike 0.1.8 style guide; the evidence is in
`docs/adobe/evidence/ui-kit/uxp-live-018/` and the record in `docs/adobe/uxp-parity.md` under the CSS lab table):
- **Documented deviation from Addendum B (amends the CTA note above): the main CTA wears a solid 1 px ring, not a
  glow.** The 10 px blur of `--twn-cta-glow` painted no visible glow in the 018 shots. The CTA now uses
  `--twn-cta-ring: 0 0 0 1px #D95C9B` (a box-shadow spread with no blur: the form the focus ring proves paints) and that
  ring **alone**, because combining it with the glow would need a multi-shadow value, which is unproven in UXP.
  `--twn-cta-glow` stays defined in `brand/tokens.css`. The next live shot confirms the ring.
- The Arabic progress bar filled from the left in UXP (the flex row did not mirror through `direction`). Under
  `.kit-rtl` the track is now `direction: ltr; justify-content: flex-end` and the fill has `margin-left: auto`, all
  physical, so it fills from the right in UXP and Chromium alike.
- Engine text in the kit goes through `runtimeText()` (C2.2): the progress status and the frame labels, as the toast
  already did. Space activates a control on keyup (Enter on keydown); auto-repeat never activates; a mouse press on a
  disabled control does not take the focus. After a repaint the focus returns to the control the editor used.
- `test/btn-debt.ts` pins the `<button>` count left in `render.ts` (13). It may only go down; B-T2 brings it to 0.
