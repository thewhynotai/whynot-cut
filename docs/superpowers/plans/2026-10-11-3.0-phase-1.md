## Global Constraints (bind every task)

- Repo root = the folder that contains `PROGRESS.md` (being renamed from `whynot-cut-marketplace` to `WhyNotCut`).
  The plugin is `whynot-cut/`. Branch `release/3.0`. One commit per task, conventional message, ending with the line
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Tests run only with the engine venv** (system Python silently skips HarfBuzz tests). From the repo root:
  `PYTHONDONTWRITEBYTECODE=1 PYTHONUTF8=1 ~/.whynot-cut/venv/Scripts/python.exe -B -m unittest discover -s whynot-cut/tests`
  (≈8 min; `tools/test.sh` does the same). Focused: add `-k <pattern>`. Never use `-I`/`-s` with this venv (its
  packages are in the user site until Phase 2 T2.1).
- TDD: every behaviour change gets a test that fails before the change. The total test count must never go down.
- Never write into `D:\WhyNot Clients` or into any real client folder. Test clients are copies under
  `../whynot-test/` (sibling of the repo).
- Bash heredocs mangle `\n` and Arabic text: write files containing Arabic with the Write/Edit tools.
- Windows 11 is the dev machine; code must stay correct on macOS (POSIX paths, `fcntl`, exec bits).
- Engine stdout = one JSON document; human messages and refusals are plain English with a `how` hint.
- Keep the existing style: stdlib-first, small functions, `common.py` helpers, lazy imports in CLI handlers.
- Update `whynot-cut/CHANGELOG.md` under a new top section `## 3.0.0 (unreleased)` (create it once; later tasks append
  bullets under Added / Changed / Fixed / Migration).

### Task 3: T1.3 Clip identity (engine CR-1)

Today `slug(stem)` (`common.py`) gives inbox ids, while `main_footage()` (`cli.py`) matches the raw stem → names with
spaces are rejected and Arabic names collapse to `VIDEO`. Episodes already solved it: `episode_id_for` (`episode.py`).
- Add `clip_id_for(path, taken=...)` (in `common.py` or a new small `lib/clip_ids.py`): ASCII slug + short stable hash
  for non-ASCII or colliding names (same rule as `episode_id_for`; reuse/share its helper rather than duplicating),
  plus a de-dup suffix for the same stem with different extensions (`C0239.MP4` vs `C0239.mov`). ASCII-only names that
  don't collide keep their current slug so existing projects keep their ids.
- Persist the map in `output/discovery/clip-ids.json` (`{id: relative_path}`), written atomically; stable across runs
  (an id never changes once assigned).
- `main_footage()` resolves an id, the raw stem or the old slug through the map.
- `inbox` (`onboard.py`) and `cli.main` auto-fill use it.
- **Acceptance:** tests with names containing spaces, Arabic, Arabic-Indic digits (`مقابلة ١.mp4`, `مقابلة ٢.mp4`),
  duplicate stems with different extensions, and ≥2 clips per client. Two Arabic clips never share a project folder;
  every id `inbox` hands out is accepted by a per-clip command (`--video-id`).

### Task 5: T1.5 Guard hardening (structure 4.1, 4.2, 4.5, 4.7; engine IM-17, §10)

Files: `whynot-cut/hooks/guard.py`, `hooks/run_python.sh`, `hooks/session_context.py`, `engine/reel/lib/onboard.py`
(scaffold), `cli.py` (`client-init`, `doctor`).
1. **Positive client marker.** A folder is a client folder only if it has a `.whynot-client` file, OR it lies under the
   configured `clients_root` (read the same settings the engine reads: `~/.claude/whynot-cut.local.md` /
   `plat.clients_root_setting()`), OR it has `output/client_database/`. `scaffold`/`client-init` write `.whynot-client`
   (small JSON: `{"whynot_client": 1, "created": ...}`) at the client root; `doctor --fix` writes it for an existing
   client that lacks it (only into the client root, never into `assets/` or `data/`).
2. **`run_python.sh`:** try the engine runtime Python first (`$WHYNOT_HOME`/`~/.whynot-cut` venv:
   `venv/Scripts/python.exe` or `venv/bin/python`); skip `*/WindowsApps/*` stubs; on macOS skip `/usr/bin/python3`
   when `xcode-select -p` fails; cache the resolved interpreter path in `${CLAUDE_PLUGIN_DATA}/python` (when the var is
   set) and `exec` it; drop the separate version probe (guard.py/session_context.py check `sys.version_info`
   themselves); write a heartbeat file `${CLAUDE_PLUGIN_DATA}/hooks-ok` (timestamp) on every successful run.
3. **No silent failure.** If no Python is found, `run_python.sh` prints to stdout a SessionStart-compatible context
   line "WhyNot Cut protection is OFF: no Python found — run reel doctor" when called for session_context, and exits 0
   (fail-open stays, but visible). `session_context.py` warns loudly when the heartbeat is stale/missing.
   `reel doctor` reports `guard_active` (true when `hooks-ok` is fresh < 24 h; look for it under
   `~/.claude/plugins/data/whynot-cut-*/hooks-ok`) with a fix hint ("install Git for Windows" on Windows).
4. **Close the bypasses** (each must be blocked when it targets a protected client source path):
   - a PowerShell pipeline whose earlier stage names a protected path and whose later stage is a mutator
     (`Get-ChildItem data/Raw | Remove-Item`);
   - `xargs <mutator>` (`ls data/Raw/*.mp4 | xargs rm`);
   - `$( … )` and backtick bodies (`echo $(rm data/Raw/a.mp4)`);
   - `[IO.File]::`/`[System.IO.File]::` write/delete/move/copy calls;
   - `git -C <protected> checkout|reset|clean|rm|mv` (and `git checkout -- data/...`);
   - `cmd /c reg add …` and `powershell -Command "Set-ItemProperty …"` aimed at Adobe CSXS keys (PlayerDebugMode).
5. **Role holes:** subagents may not run `transcript-verify --by editor`; qc-reviewer may not run `ref-analyze`;
   setup-doctor may not run `reel setup`.
6. **Role match** on the full `whynot-cut:<name>` agent type (another plugin's `qc-reviewer` is not restricted).
- **Acceptance:** one guard test per bypass and per role hole; a Hugo-layout folder (`assets/` + `data/`, no marker,
  not under clients_root) is **not** blocked and gets no client context; existing guard tests still pass (update their
  fixtures to create a marker); measured guard latency (`bash run_python.sh guard.py` with a trivial input, 5 runs)
  before and after recorded in the report — target < 200 ms on this PC.

### Task 8: T1.8 One writer per client folder (chats-other friction)

- `output/.whynot-lock` holds `{session_id, pid, host, started_at, command}`; stale after 2 h or when the pid is not
  alive on the same host. Writing commands acquire it for their duration (decorator/context manager around the
  writing subcommands in `cli.py`, `podcast_cli.py`, `motion_cli.py`; read-only ones — `next`, `status`, `doctor`,
  `inbox` without refresh, `ppro-status`, `ae-status`, `settings` show — don't). Re-entrant for the same session id
  (`CLAUDE_SESSION_ID` env if present, else pid-based) so one session's sequential commands never block each other.
- `reel lock --status` and `reel lock --release` (release is editor-only: the guard blocks it for subagents).
- SessionStart (`session_context.py`) warns "another session is working in this client (<command>, since <time>)".
- **Acceptance:** a test with two concurrent writers (two processes or a held lock with a foreign session id and a live
  pid): the second gets `{"blocked": ..., "how": ...}` JSON and a non-zero exit; stale lock (dead pid / >2 h) is taken
  over with a log line.
