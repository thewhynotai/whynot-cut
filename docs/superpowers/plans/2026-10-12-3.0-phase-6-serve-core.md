## Task 2: `serve/ws.py` — stdlib HTTP + WebSocket transport

Files: `whynot-cut/engine/reel/serve/__init__.py` (empty docstring module), `serve/ws.py`, tests
`whynot-cut/tests/test_serve_ws.py`.

- `parse_http(reader, limit=8192)` → `Request(method, path, version, headers: dict[str,str] lower-cased keys, peer)`;
  reject oversize headers / bad request lines (400, closed).
- HTTP responses (`Response(status, headers, body)`; JSON helper) with `Connection: close`.
- WebSocket upgrade per RFC 6455: GET, `Upgrade: websocket`, `Connection` contains `upgrade`, `Sec-WebSocket-Version:
  13`, `Sec-WebSocket-Key` (16-byte base64) → `101` with `Sec-WebSocket-Accept`; no extensions, no subprotocols.
- `WebSocket`: `recv() -> str | None` (None after close), `send(str)`, `close(code, reason)`, `ping()`; client frames
  MUST be masked (else close 1002); RSV bits set → 1002; binary → 1003; text must be valid UTF-8 (1007); fragmented
  messages reassembled; control frames ≤125 bytes, not fragmented; ping → pong; per-frame and per-message size cap
  (`max_message`, default 1 MiB, settable per connection) → close 1009; idle timeout.
- `start_server(handler, host="127.0.0.1", port=0) -> (server, port)`; `handler(reader, writer)` is the app hook
  (Task 4 provides the app). Refuse any host other than `127.0.0.1` at this layer (ValueError).
- Tests with real loopback sockets and a hand-written client (masking, fragmentation, ping, close codes, oversize,
  unmasked, binary, bad UTF-8, bad handshake, header too large). Every socket closed (ResourceWarning = error).

## Task 4: `serve/app.py` + `serve/router.py` — sessions, routing, adapters, context

Files: `serve/app.py`, `serve/router.py`, `serve/adapters.py`, a minimal edit to `whynot-cut/engine/reel/lib/common.py`
(strict-context switch only), tests `whynot-cut/tests/test_serve_app.py`.

- App (`handler(reader, writer)` for `ws.start_server`): HTTP `GET /status` (Bearer token required; returns
  `{protocol, daemon_version, pid, port, sessions:[{kind, host, hostVersion, capabilities}], uptime_s}`), every other
  path 404; WebSocket `/session`: Host + Origin checked BEFORE upgrade (403 + audit); first message must be a valid
  `hello` within 3 s with the right token (else `error{code:"auth"}` + close 1008 + audit); pre-auth max message 16
  KiB, post-auth 8 MiB; per-session rate limit; every message validated against `session.schema.json` (`schema`
  error, connection kept); unknown `type` → `unknown_type`.
- Router: `command` → `validate_request` (schema error if invalid; expired `expires_at` → `timeout` error) → pick an
  adapter: a connected UXP session whose `capabilities` include the action and whose host matches the action's host →
  `UxpAdapter`; else the action has a `cep` name in `protocol.json` → `FileQueueAdapter`; else `no_route`.
  Results go back as `result` messages with the request `id`; adapter results are validated with `validate_result`
  (an invalid result becomes `ok:false, error:"host answered outside the contract"` + audit). No arbitrary-script
  path exists anywhere (test: the router has no action that evaluates code; unknown actions are rejected by schema).
- `FileQueueAdapter`: runs the existing `lib.ppro_bridge.submit` / `lib.ae_bridge.submit` (import inside the call)
  in a worker thread (`asyncio.to_thread`, which copies the contextvar) and maps with `contract.cep.from_cep`
  (forwarding the outer error when `response` is None). Tests patch `submit`/`status` — never a live queue.
- `UxpAdapter`: sends `command` to the chosen session, awaits its `result` by id with timeout, relays `progress`
  events to the requester; disconnect → pending commands fail with a clear error; reconnect = new hello.
- Context: each `command` builds `Context(root, profile, home=<daemon home>)` and runs inside `use_context`.
  `common.py`: add `require_bound_context(on: bool = True)` (module flag) — when on, `current_context()` raises
  `RuntimeError("no request context bound — reel serve must bind one per request")` if nothing is bound; the serve
  process turns it on at start. Add a test in `test_serve_app.py`; do not change other `common.py` behaviour.
- Tests: in-process server on a temp home with fake adapters + real loopback clients: auth ok/bad, schema error,
  unknown action, routing choice (UXP session with capability wins; CEP fallback; no route), result validation,
  progress relay, disconnect fails pending, two concurrent commands with different roots see their own Context.

## Task 5: lifecycle, CLI entry, end-to-end security suite

Files: `serve/daemon.py` (`run(home)`, `ensure(home) -> dict`, `status(home)`, `stop(home)`), `serve/__main__.py`
(`python -m reel.serve --ensure|--status|--stop|--foreground`), tests `whynot-cut/tests/test_serve_security_e2e.py`.

- `run`: bind 127.0.0.1:0, write engine.json (port, token, pid, version, started_at), audit start/stop, remove the
  file on clean exit (pid-guarded), `require_bound_context(True)`.
- `ensure`: if engine.json exists, its pid is alive and `GET /status` answers with the token within 300 ms → return
  it (idempotent, no second daemon); else start a detached background process (Windows: `DETACHED_PROCESS |
  CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW`, POSIX: `start_new_session=True`) with the engine runtime's python and
  wait ≤ 1 s for engine.json + `/status`. Stale file (dead pid) is replaced. `status` reads + probes; `stop` asks
  the daemon to exit via an authenticated `POST /shutdown` (the only mutating HTTP endpoint; token required) and
  removes a stale file.
- CLI: do NOT edit `cli.py` (executor edits it concurrently). Provide `serve.cli.cmd_serve(args)` + its argparse
  builder so the executor can register `reel serve` in one line; write the exact table line, handler line and the
  SessionStart hook command (`reel serve --ensure`, background, idempotent) into STATUS-adobe.md.
- E2E security suite (spawns a real daemon on a temp home via `python -m reel.serve --foreground`, or in-process when
  spawning is unreliable; always torn down): wrong token, missing token, wrong Host, browser Origin (`https://…`,
  `null`, `chrome-extension://…`), oversize message, rate limit, unknown action, schema-invalid data → each rejected
  AND present in the audit log without the token; reconnect after disconnect; `::1` not bound (connect to `[::1]:port`
  fails); `0.0.0.0` not bound (connect via a non-loopback local address fails when one exists, else skip with
  reason); `--ensure` twice → same pid; `--stop` → port closed and engine.json gone.
