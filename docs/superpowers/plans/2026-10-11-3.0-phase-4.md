# WhyNot Cut 3.0 — Phase 4: editor features from the field tests

Spec: master plan §7 Phase 4 (T4.1–T4.9). Evidence: `docs/review/2026-10-11/chats-main.md` §5 and §8 (zoom/fades,
caption size, captions vs hook, standing rules, no-questions run), `chats-other.md` (episode sheet, brand material
missing early, moving to another device), `chats-podcast-motion.md` (motion music).

## Global Constraints (bind every task)

- Repo root `WhyNotCut/`; plugin `whynot-cut/`; branch `release/3.0`; one commit per task (conventional message ending
  with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`). Tests `bash tools/test.sh`. TDD; count never drops.
- Client `assets/` and `data/` are read-only; everything the engine writes goes to `output/`.
- Never invent licences; never write into `D:\WhyNot Clients`; test clients are copies in `../whynot-test/`.
- New behaviour must be reachable from the skills (update the relevant SKILL.md / agent text in the same task).
- Bridge-side changes (JSX/JS) must keep CEP read-back working; UXP parity is done in Phase 6 (record the needed op in
  `docs/adobe/uxp-parity.md` "pending ops" list when you add a host op).

### Task 1: T4.1 Smooth zoom and fades [P1]

`camera.ease` keyframes on Motion Scale/Position for punch-ins (ease in/out; duration from `style.json`
`camera.ease_ms`, default e.g. 250 ms) in the timeline-spec, the CEP build (`nh_ppro_lib.jsx`/`wnc_*` keyframes with
bezier/ease interpolation) and the preview-video renderer; optional fade in/out of picture and audio at reel start/end
(`style.json` `fades: {video_in_ms, video_out_ms, audio_in_ms, audio_out_ms}`). Read-back reports keyframe counts and
interpolation per punch-in.
- **Acceptance:** spec/unit tests for keyframe generation; preview-video frame test shows intermediate scale during
  the ease; read-back fields present (mocked bridge). Live at Gate 4.

### Task 2: T4.2 Style knobs that plan reads [P1]

`reel-profile/style.json` defaults applied by `compile_plan`: caption size (+ per-reel override in edit-decisions),
captions hidden during the hook (per client), hook-title SFX on/off, highlight colour policy (with G68 contrast).
- **Acceptance:** tests that change style.json → a different timeline-spec for each knob.

### Task 3: T4.3 Learning loop [P1]

`revise` (skill + a small engine helper `reel rules --propose|--add`) detects recurring feedback ("always…",
"never…", «دايماً», «أبداً», the same comment on 2+ reels via `output/**/revision-notes.json` history) and proposes
standing rules; on editor confirmation they are written to the client's `reel-profile/notes.md` (dated entry) and, for
machine-applicable knobs, `style.json`.
- **Acceptance:** tests for detection (EN + AR) and the dated write; guard: subagents can't `rules --add`.

### Task 4: T4.4 Episode sheet [P1]

`reel episode-sheet --init EP12` writes a filled template (episode id, guests with gender/honorific fields linked to
`people[]`, topics, sponsor, links, publish date) to `output/episodes/EP12/EP12.md`, prints where to move it
(`data/Episodes/`), never writes into `data/`.
- **Acceptance:** test output path + content fields; refusal when it would write into data/.

### Task 5: T4.5 Portable client database [P1]

All paths in `output/client_database/**` relative to the client root (migrate absolute ones on read: rewrite when they
point inside the client root); `reel client-move --to <new root>` verifies and rewrites; `reel client-clone --to <dir>`
copies the client database/profile without media.
- **Acceptance:** a client moved to another drive/folder (temp dirs) passes `reel next` with no stale flags; clone test.

### Task 6: T4.6 Music in motion videos [P1]

Licensed tracks from `data/Music` (with a required licence file per track or folder) chosen by recipe mood, ducked
under dialogue (level keyframes), as an AE audio layer in `motion-build`; never invent licences; no licence → no music
+ a NEEDS-YOU item.
- **Acceptance:** motion-plan tests for track selection/ducking keyframes; refusal without licence; fake-AE build test.

### Task 7: T4.7 No-questions autopilot + one checklist [P1]

With `approval: auto`, autopilot runs every new clip or episode to QC (delegated approvals recorded as
`by: "auto"`), and writes one `output/NEEDS-YOU.md` per client (engine `reel needs-you --write`): words to confirm by
ear; medical/religious approvals; music; fonts and logo missing; final mix/render. Idempotent, regenerated from state.
The panel (Phase 6) shows the same list (JSON twin `output/needs-you.json`).
- **Acceptance:** engine tests building NEEDS-YOU from fixture state; autopilot skill text; approval-auto recorded
  distinctly from editor approval.

### Task 8: T4.8 Early warnings at intake [P1]

At `start`/`new-client`/`inbox`: episode files found in `data/Raw` (suggest `data/Episodes`); documents in
`data/References`; missing logo, HEX, fonts, episode sheet → reported early (inbox JSON `warnings[]` + session context
one-liner), not at build time. Name supers detection (G65) stays.
- **Acceptance:** inbox tests per warning.

### Task 9: T4.9 Adopt old per-video styles [P2→P1 if time]

`reel ref-style --adopt <ID>` merges a per-video style (old 2.1 per-clip style files) into the client-level style with
a diff shown first and `--yes` to write.
- **Acceptance:** merge test.
