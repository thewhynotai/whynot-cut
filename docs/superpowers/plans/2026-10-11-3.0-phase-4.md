### Task 10: T4.10 G-GPU engine acceleration [P1]

**Goal:** heavy media steps use the GPU when it works and the CPU when it doesn't, without the editor noticing. FFmpeg
uses NVDEC/NVENC (`-hwaccel cuda`, `h264_nvenc`/`hevc_nvenc`) on NVIDIA and VideoToolbox on macOS, for intermediates
only: preview-video (the proxy), reel candidates, the motion animatic, frame extraction and the frames grabbed for
caption-still compositing. Finals stay libx264 (`motion_render.render` MP4, crf 18). One GPU-heavy engine job runs at
a time. GPU jobs wait, or take the CPU path, while Premiere or AE exports or renders.

**Interfaces (produced):**
- `accel.detect(ff: str | None = None, *, system: str | None = None, runner=subprocess.run, refresh: bool = False) -> dict`
  → `{"kind": "cuda" | "videotoolbox" | "cpu", "h264": str, "hevc": str | None, "decode": list[str], "name": str | None, "why": str | None}`.
  It probes `ffmpeg -hide_banner -encoders`, then a real 0.1 s `lavfi` encode with the GPU encoder. Listed-but-unusable
  means `cpu` with `why`. The result is cached in `<home>/cache/accel.json`, keyed by the ffmpeg path, size and
  `mtime_ns`. `WHYNOT_ACCEL=off` gives `cpu`, why "turned off (WHYNOT_ACCEL=off)".
- `accel.decode_args(lane: str) -> list[str]`: `[]` | `["-hwaccel", "cuda"]` | `["-hwaccel", "videotoolbox"]`
  (frames go back to system memory: the CPU filters and rawvideo pipes stay unchanged).
- `accel.h264_args(lane: str, crf: int) -> list[str]`: cpu = exactly today's
  `["-c:v", "libx264", "-preset", "veryfast", "-crf", str(crf)]`; cuda =
  `["-c:v", "h264_nvenc", "-preset", "p4", "-rc", "vbr", "-cq", str(crf), "-b:v", "0"]`; videotoolbox =
  `["-c:v", "h264_videotoolbox", "-q:v", str(VT_Q[crf])]` with `VT_Q = {18: 75, 23: 65, 28: 55}`. The A/B (step 8)
  may change these numbers, never the shape.
- `accel.SITE_LANES: dict[str, str]`: per call site ("preview_video", "reel_candidates", "animatic", "thumbs",
  "shots", "grab_frame"), `"gpu"` or `"cpu"`, set from the A/B. `"grab_frame"` starts as `"cpu"`: a single frame pays
  the CUDA start-up cost.
- `accel.is_gpu_failure(stderr: str) -> bool`: matches NVENC/NVDEC/CUDA/VideoToolbox errors, including
  "OpenEncodeSessionEx failed", "No capable devices found", "CUDA_ERROR_OUT_OF_MEMORY", "out of memory",
  "Cannot load nvcuda", "VTCompressionSessionCreate".
- `accel.run_ff(build: Callable[[str], list], lane: str, *, log_to=None, runner=None) -> tuple[subprocess.CompletedProcess, str]`:
  runs `build(lane)`. On a GPU failure it runs `build("cpu")` once and logs `GPU_FALLBACK_EN`
  ("The graphics card couldn't do this step (it may be busy or out of memory), so the processor did it: slower, same
  result."), plus `GPU_FALLBACK_AR`. It returns the lane actually used.
- `gpu_lock.host_busy(queues: list[Path] | None = None) -> str | None`: reads `bridge.heartbeat` in
  `ppro_bridge.queue_dir()` and `ae_bridge.queue_dir()` through `cep_queue.status()`. It returns `"exporting"` or
  `"rendering"` only from a live heartbeat whose `host_busy` field says so. An absent field, `"idle"`, `"unknown"`, any
  other value or a stale heartbeat gives `None` (unknown = proceed). The field comes from the Adobe track (hardening
  plan H6).
- `gpu_lock.gpu_slot(what: str, *, wait_s: float = 0.0, poll_s: float = 2.0, clock=time.monotonic, sleep=time.sleep) -> ContextManager[str]`:
  yields the lane (`"cuda"`, `"videotoolbox"` or `"cpu"`). On a `cpu` machine it yields `"cpu"` at once, with no lock.
  Otherwise it waits up to `wait_s` in total, first while `host_busy()` is set, then for
  `file_lock.locked(<home>/locks/gpu, wait_s=remaining)`. A `LockTimeout` or a host still busy yields `"cpu"` with one
  log line naming why. While held it writes `<home>/locks/gpu.json {pid, what, since}`; that record is only for
  messages, the OS lock decides. `gpu_lock.held() -> dict | None` is the non-blocking check T4.15 uses.
- Waits per caller: `transcribe` 600 s; `preview_video` and `reel_candidates` 120 s; everything else 0 (CPU at once).
- `whisper_backends.make_runner(..., device: str | None = None)`: `device="cpu"` loads on the CPU (passed through to
  `load_ct2`).

### Task 11: T4.11 G13-RUN lean runtime, engine part [P1]

**Goal:** on a customer's machine the engine is invisible while idle and polite while working:
- idle `reel serve` < 100 MB RAM and ~0 % CPU;
- Whisper loads only for a job and is released after it;
- the GPU batch size fits the free VRAM, leaving room for Premiere;
- background `reel` work runs at BelowNormal.

BelowNormal is a product setting, **on by default**. It differs from the dev-PC policy: on Yunus's PC the build and
test work runs at Normal priority with full resources (heavy.sh). Dev live runs pass `WHYNOT_PRIORITY=normal`, and the
suite sets it in `_isolation.py`. `reel serve` code is the Adobe track's (locked; its idle wakeups are H6), so here it
is measured, not changed.

  `cli.py` `main()` (after parsing: `if a.cmd != "serve": priority.apply()`); `lib/whisper_backends.py` (VRAM fit,
  `run.release()`); `lib/transcribe.py` `transcribe()` and `relisten()` (`run.release()` in `finally`);

**Interfaces (produced):**
- `priority.apply(setting: str | None = None, *, os_name: str | None = None, setter=None, env=os.environ) -> str`:
  returns `"below_normal"`, `"normal"` or `"unsupported"`. `WHYNOT_PRIORITY` beats the setting.
  - Windows: `SetPriorityClass(GetCurrentProcess(), 0x4000)` (ffmpeg children inherit BELOW_NORMAL).
  - POSIX and macOS: `os.nice(10)` (inherited).
  - Never raises; a refusal returns `"unsupported"`.
- `whisper_backends.vram_free_mb(runner=subprocess.run) -> int | None`: `nvidia-smi --query-gpu=memory.free
  --format=csv,noheader,nounits`, first GPU, 10 s timeout; None on any failure.
- `whisper_backends.fit_batch(model: str, compute_type: str, configured: int, free_mb: int | None) -> tuple[int, str]`
  → `(batch_size, "cuda" | "cpu")`:
  - `need(bs) = MODEL_VRAM_MB[(model, compute_type)] + PER_BATCH_MB * max(bs, 1) + HEADROOM_MB`;
  - take the largest `bs ≤ configured` that fits; batch 1 counts as sequential (0), as `set_batch` already does;
  - nothing fits → `"cpu"`;
  - `free_mb is None` → `(configured, "cuda")`, today's behaviour (the OOM path still guards).
