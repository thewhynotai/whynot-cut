### Task 1: T2.1 Self-contained runtime and real repair (IM-1, IM-2, MI-21)

- New layout `~/.whynot-cut/runtimes/<runtime-id>/` (venv-style env built from a pinned Python 3.12; prefer `uv` +
  python-build-standalone when available, else the system `py -3.12`), plus `~/.whynot-cut/current` pointer file (text
  file with the runtime id — not a symlink, Windows-safe). The legacy `venv/` keeps working as a fallback when no
  runtime exists.
- Remove `--system-site-packages` from the normal path of `setup/setup_env.py` (keep a hidden dev flag that installs
  with `--ignore-installed`).
- Hash-locked `setup/locks/runtime-win-x64.lock`, `runtime-mac-arm64.lock`, `runtime-mac-x64.lock` (`uv pip compile
  --universal --generate-hashes` per platform marker, or pip-tools if uv isn't available). Keep `requirements.txt` as
  the human-edited ranges file. Store the lock's sha256 inside the runtime (`.whynot-lock.sha256`).
- `reel setup` runs setup_env (install/repair when module versions don't satisfy the lock or the hash differs; pip
  `--timeout 60 --retries 5`, `--require-hashes`).
- `bin/reel` and `reel.cmd` resolve the runtime python (`current` → runtime → legacy venv) and run the engine with
  `python -s`.
- `reel doctor` checks every engine module's `__file__` is inside the runtime and its version satisfies the lock →
  `isolated: true|false` with a fix hint.
- **Rebuild this PC's runtime side by side** and run the full suite on it (`tools/test.sh` picks `current`).
- `reel py <script|-m mod> [args]` (also T2.16) runs with the engine runtime.
- **Acceptance:** doctor shows `isolated: true` on the new runtime; suite green on it; unit tests for lock parsing,
  runtime resolution order and the repair decision (versions/hash differ → reinstall).

### Task 2: T2.2 Errors and exit codes (IM-7, MI-24)

Top-level handler in `cli.main`: `SystemExit` as is; known exceptions (`json.JSONDecodeError`, `KeyError`,
`ValueError`, `FileNotFoundError`, `PermissionError`, `subprocess.TimeoutExpired`, `IndexError` in known places) →
`{"ok": false, "error", "where", "how"}`, exit 1, traceback appended to the project/client `logs/pipeline.log`.
`out()` exits 1 on `ok: false` or a FAILED/REFUSED/BLOCKED status. `read_json` and `settings.parse` use `utf-8-sig`
and re-raise decode errors with file + line. `compile_plan` validates required fields before use.
- **Acceptance:** tests for a decision without `start`, a BOM JSON, `ref-analyze` before `discover`, silent audio in
  `_loudness`, an ffmpeg/aerender timeout → guidance JSON, no traceback on stdout/stderr, exit 1 (refusals stay 2).

### Task 19: Guard minors carried from Phase 1 (gate review)

In `whynot-cut/hooks/guard.py` / `hooks/session_context.py` (threat model: accidental commands; keep latency < 200 ms;
regression harness under the executor scratchpad `harness/` must stay at 0 mismatches):
- Bash: a backslash before CRLF is NOT a continuation (`ls output \` CRLF `rm -rf data` → block); an escaped `\$'`
  must not open ANSI-C quoting; a line ending in `\` followed by a line starting with `#` joins (`ls output\⏎#; rm -rf
  data` → block); `$((1 << bits))` arithmetic is not a heredoc start.
- PowerShell: backtick + CRLF is a continuation (normalise `\r\n` → `\n` in `check_powershell` only).
- Heartbeat: no "protection may be OFF" warning after a session that only read/chatted followed by `/clear` or a new
  session (e.g. compare against the last SessionStart that was followed by any guarded tool call, or warn only when
  a guarded tool call failed to refresh guard-ok within the same session).
