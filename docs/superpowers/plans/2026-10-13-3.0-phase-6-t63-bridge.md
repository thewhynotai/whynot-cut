## Design decisions (binding)
1. **The JSX libraries stay in `whynot-cut/templates/**` as their single source.**
   - `package.py` never ships `adobe/`.
   - The engine embeds the libraries in standalone AE/PS scripts, syncs them for the legacy family, and hashes them
     for the handshake.
   - Only the CEP **shell** moves to `adobe/cep-bridge/` (`CSXS/manifest.xml`, `index.html`→`ui/index.html`,
     `js/bridge.js`, `jsx/host.jsx`→`jsx/wnc_host.jsx`). The bundle build copies the libraries into `jsx/`; that copy
     is an artefact, not a second source.
2. **Ids are unchanged:** bundle `ai.thewhynot.cut.bridge`, extensions `.panel` / `.daemon`. Only the visible names
   become "WhyNot Cut". A new id would leave 3.1.1 loaded beside the new one.
3. **Two families during 3.0:**
   - **Bundle 3.0.0.** The heartbeat is `{at, busy, role, host, hostVersion, bundle, version(=bundle), protocol:4,
     build, libs{name:sha256}, current, action}`. Jobs carry `lib:"<wnc file>"`, resolved inside `<ext>/jsx/`.
   - **Legacy, exactly 3.1.1.** It has no `protocol`. The engine syncs the renamed libraries and sends `script:`. The
     libraries define the aliases `var NHPP = WNCPP;` and `var NHAE = WNCAE;`, removed in 3.1.
   - Every other version is refused.
4. **New engine module `whynot-cut/engine/reel/lib/cep_bundle.py`** (Adobe-track owned). It holds `source_dir`,
   `assemble`, `build.json`, `expected_libs`, `installed`, `decide_install`, `install_zxp`, `config_path`,
   `write_config` and `family`. Executor-owned files only get delegating hunks.
5. **`~/.whynot-cut/bridge/config.json`** (always under the user home, user-only, no secret, never inside the
   extension):

   ```json
   {"schema":1, "engine_home":"<abs>", "launcher":"<abs>|null", "written_by":"installer|engine", "at":"<iso>"}
   ```
6. **The bundle's `build.json`:**

   ```json
   {"product":"3.0.0", "build":"<16 hex of sha256 over sorted (path, sha256)>", "sha":"<git|null>", "protocol":4,
    "libs":{"wnc_ppro_lib.jsx":"<sha256>", "...": "..."}}
   ```

### Task 5 — the daemon spawns only the fixed launcher; After Effects panel states; doctor; docs
- **`bridge.js` daemon role only.**
  - **When:** at start and every 30 s while `~/.whynot-cut/bridge/engine.json` is missing or its pid is dead. Only the
    pid is parsed; the token is never kept or logged.
  - **What it spawns:** `config.json` `launcher`, which must be:
    - absolute and a regular file;
    - with a realpath equal to `realpath(engine_home)/bin/wnc-engine.cmd` (win32) or `wnc-engine` (darwin);
    - on POSIX, owned by the user and not group- or world-writable.

    Metacharacters ``" % ^ & | < > !`` are refused.
  - **How:** win32 `spawn(ComSpec, ["/d","/s","/c", "\"<launcher>\""], {detached, windowsHide, stdio:"ignore",
    cwd:engine_home}).unref()`; POSIX `spawn(launcher, [])`. No arguments.
  - **Limits:** at most one attempt per 30 s, and it stops after 5 failures. The heartbeat gains `engine_start`.
- **`cep_bundle.write_config`** fills `launcher` when the file exists.
- **After Effects panel `ui/`:** one sentence per state (running · busy · "WhyNot Cut isn't running in After Effects:
  restart After Effects" · "Starting WhyNot Cut…"), plus Copy diagnostics. It uses the tokens and shows no commands.
- **`onboard.bridge_info()` hunk:** reads `config.json` plus the installed `build.json`.
- **New `docs/adobe/cep-bridge.md`:** layout, every shape, the install rule, the spawn allowlist and the legacy family.
