## Measured facts the adapter must encode

1. **`project.path` carries the Windows extended-length prefix and mixed slashes**: the string is `\\?\D:/0 Work/.../spike-...prproj` (raw JSON `"\\\\?\\D:/..."`). Compare paths only after stripping the prefix and normalising (`\\?\UNC\` -> `//`), as the spike's `cleanPath` / `normPath` do; the 0.1.0 guard failed exactly here. Which form `Project.open` needs is unverified (O2).
2. **Timing**: `createProject` 1.97 - 4.7 s normally, 19.3 s and 33.0 s twice (possibly with a modal waiting); first `importFiles(xml)` 7.6 s cold, 0.2 - 0.4 s warm; `project.save()` 1.3 - 7.7 s; `close` 65 - 152 ms; every API call inside a probe (keyframes, effects, markers, renames) 0 - 5 ms. Use 180 s timeouts for create, import, save, open.

## Dialogs (modal dialogs block automation)

Both dialogs appeared during the save / close / reopen step of the 0.1.1 runs. Yunus answered **Yes** (Scratch Disk
Error) and **OK** (Project Modified) every time. Despite that, the reopen failed 3 of 3 times (`Failed to open the project`).

| Dialog | Text | Likely trigger (inferred; the spike did not log it) | Notes |
|---|---|---|---|
| Scratch Disk Error | "The scratch disks are write protected or unavailable. To open this project, the scratch disks will be set to your My Documents folder." (Yes / No) | Opening a project whose scratch-disk settings point at an unavailable location: the `Project.open` step (the sentence says "to open this project"), and possibly `createProject` itself, which also opens the new project (the 19 - 33 s `createProject` times fit a modal waiting for a click). The `\\?\` project path is a suspect for "unavailable"; the work folder does contain an `Adobe Premiere Pro Auto-Save` subfolder, so "Same as project" resolved at least for auto-save | `OpenProjectOptions.setShowWarningDialog(false)` and `setShowLocateFileDialog(false)` did not prevent it. The d.ts offers `ProjectSettings.createSetScratchDiskSettingsAction(project, settings)` with `ScratchDiskSettings.setScratchDiskPath(ScratchDiskFolderType.*, ScratchDiskFolder.SAME_AS_PROJECT)` and `ProjectSettings.getScratchDiskSettings(project)`: **to try in 0.1.2** right after `createProject` |
| Project Modified | "The project file has been modified since last save. Do you wish to continue?" (OK / Cancel) | `project.save()`: the three save steps took 2 233 / 1 319 / 7 659 ms against 65 - 152 ms for `close` (which had `setPromptIfDirty(false)`), consistent with a person clicking a modal. Premiere shows this when the file on disk is newer than the in-memory copy, which fits `createProject` having written the file and something touching it afterwards | which step is not confirmed; it was not noted during the runs |

Consequence: until both are understood, `build_project` through UXP cannot run unattended. The daemon must treat
`create_project`, `save` and `open` as possibly blocked by a modal (long timeouts, and the CEP compat op as the

## Spike defects to fix in 0.1.2 (the spike was wrong, not necessarily the API)

1. **Gaussian Blur picked the wrong effect** (E4). The candidate list was `[...viaDisplay, ...byMatch]`; the display name "Gaussian Blur" is `AE.Impact_Blur_FX` (Amount / Angle / ...), the Blurriness effect is `AE.ADBE Gaussian Blur 2`. Pick `AE.ADBE Gaussian Blur 2` (and dump `AE.Impact_Blur_FX` separately), set Blurriness 90 and Repeat Edge Pixels with `createSetValueAction`, read back with `getValueAtTime`.
2. **Crop looked for the wrong thing** (K5). `/ADBE Crop/` does not match `AE.ADBE AECrop`, and the engine animates the Motion component's own `Crop Left` anyway (param 7 of `AE.ADBE Motion`). Keyframe `Crop Left` (0 -> 100) and read back; optionally append `AE.ADBE AECrop`.
3. **Position keyframe not isolated** (K4). Log type, keys and values of `getStartValue().value.value` and of `getValueAtTime`, build the keyframe from a `PointF` made of those numbers (watch normalised 0 - 1 vs pixel units), and wrap `createKeyframe`, `createSetTimeVaryingAction` and `createAddKeyframeAction` in separate steps so the failing call is named.
4. **Time basis could not be decided** (K7). The chosen clip's local and sequence windows overlap, the three bases were keyed on three different params, nothing was rendered, and the read-back only mirrors the input. In 0.1.2: pick or build a clip whose local `[0, dur]`, media `[in, in + dur]` and sequence `[start, end]` windows are pairwise disjoint, key a visible change (opacity 100 -> 0 over 1 s) in ONE basis at a time on the same clip (remove the keys between runs), and decide by exported frames at known sequence times (needs defect 6). Repeat for a placed still (in-point 3599.96 s).
5. **Preview codec sent the wrong form** (S3). The getter returns a display name (`"Animation"`); the probe sent `"apcs"`. Try the display name of ProRes 422 LT, then the FourCC, with `setPreviewFileFormat("QuickTime")` first; keep the setter's return value in the info even when the read-back differs (the `apply` helper discarded it by throwing).
6. **Frame export tried too few forms and logged too little** (Q1). Both calls returned `false` without throwing. Try native backslash paths, a path without spaces (`C:/temp/`, as in the d.ts example), `filepath` without a trailing slash, jpg / tif, and a frame time inside a clip; confirm the sequence is the active one; poll the file for up to 5 s; log the returned value and the media-online state (one project item, `whoosh_soft.wav`, is offline); if still false, run an `EncoderManager` export of a 1 s range and extract frames with ffmpeg.
7. **save / close / reopen gave no attribution** (O2, O3, Dialogs). Add `Date.now()` stamps before and after each step, read `getScratchDiskSettings` right after `createProject`, set scratch to SAME_AS_PROJECT with `createSetScratchDiskSettingsAction`, then save, close, and reopen with (a) default `OpenProjectOptions` and (b) the cleaned path vs the raw `\\?\` path; note per run which dialog showed up and at which step.
8. **`Application.version` counts as a failed step every run** (P2). Use `uxp.host.version` as the source and downgrade `Application.version` to an informational step, so `host_info` ends clean.
9. **Static values never set** (K8). Add explicit `createSetValueAction` probes for Sharpen Amount, Noise Intensity and one numeric param with read-back (the plan relied on the blur step, which failed first).
10. **Undo check pointed at the wrong menu** (U2, U3). The `manual_check` text says the Edit menu must read "Undo WhyNot Cut build"; Premiere's Edit menu shows only "Undo" (the label is in Window > History, confirmed for U2). Change the text to: "Window > History must show 'WhyNot Cut build' as one entry; press Ctrl+Z once and check that the V1 name, the marker and the A1 name all revert". Run the `undo_transaction` probe first in a fresh project so the history is short (the kept-open project showed 32 undos, about 8 of them "WhyNot Cut build", because every probe step is its own transaction).
11. **Missing probes**: save-as, bins, `createSetEndAction` / in / out, transitions, Lumetri creation, MOGRT insert, EncoderManager export, `getProjectViewIds`, `createSequence*`, track item to project item path, persistence after reopen.
12. **Report cleanliness**: `uxp_versions: {}` in `host_info` is JSON of non-enumerable properties; read `uxp.versions.uxp` explicitly. `os.release()` returns a compat string (`6.2.9200`), so do not use it as the OS build.
