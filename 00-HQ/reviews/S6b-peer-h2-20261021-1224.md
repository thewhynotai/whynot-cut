### P2-1 — `autopilot-approval-auto` scores the skill-faithful answer as a fail
`whynot-cut/evals/autopilot-approval-auto/graders/auto-approve-command.md:7` requires `reel auto-approve` in the answer.
But no fixture writes a preferences file and `plugin.json:55-60` defaults `approval` to `ask`. So the workspace's real
setting is **ask**. Per the frozen text, `reel auto-approve` "refuses unless that client's merged preferences … say
auto" (`autopilot/SKILL.md:57-59`), and an editor saying "don't stop to ask me" in chat is a per-plan delegation:
`reel approve-plan --by delegated --note "<their words>"`, or ask "this clip only, or from now on?"
(`edit/SKILL.md:173-177`, `182-183`: approval comes from the chat or from `reel settings`). An agent that checks
`reel settings`, sees `ask` and follows the skill fails this grader. The report carries this as known limit "P2-3" and
compares it to `autopilot-new-clips`. That comparison does not hold: there the prompt's `ask` **matches** the real default,
here the prompt contradicts it. It was closed after one fix round, and a fix exists inside the fence.
**Fix (inside the fence):** let the grader also accept the delegated path, e.g.
`reel(?:\.cmd)?\s+(?:auto-approve|approve-plan[^\n]*--by[ =]delegated)` (test_evals already validates both
command/flag/choice), or drop this grader and rely on `sensitive-never-auto` + `stops-at-qc`. If an `approval: auto`
fixture is wanted, that is a fence extension (`_fixtures`) for the master to grant.
