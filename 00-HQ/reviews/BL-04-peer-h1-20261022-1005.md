### P2-1: an exit-1 failure after a torn output is recorded as FINISHED, so resume never re-runs it
- **Where:** `run_state.py:247` (`recording`: `done = isinstance(e, SystemExit) and e.code == 1 …`) together with
  `finish()` (`run_state.py:207-219`), which fingerprints whatever file is there.
- **The flaw:** exit 1 is not only "a failed check report" (qc). `errors.exit_code` gives 1 to every `ok: false` and
  to the statuses FAILED / REFUSED / BLOCKED / BRIDGE_NOT_RUNNING.
- **Concrete case:** `lib/preview_video.py:639-641` returns `{"ok": False, "video": mp4}` when the ffmpeg join fails
  or the mp4 is ≤ 1000 bytes (a cut-short preview). `cli.out` then exits 1, and `recording` records preview-video as
  finished with the torn file's size + mtime.
- **Reproduced (probe):** run_all; under `recording(ns("preview-video"))`, write a torn mp4, then `SystemExit(1)`.
  Result: `resume()` → `next == "done"`, `rerun == []`. `reel next` also says done (the file exists). So the editor
  is shown a broken preview at Gate 1.
- **Why it matters:** this breaks the spec's pre-mortem line "a missing or torn output re-runs that stage" on a
  real engine error path. The same can happen for motion-animatic / motion-render FAILED results.
- **Fix:** treat exit 1 as "ran" only for verbs whose failed result is a complete report. Use an explicit set, e.g.
  `_REPORT_ON_FAIL = {"qc", "preflight", "publish-check", "motion-plan"}` (check each against its writer). Every
  other exit 1 should go down the not-done path (undo if the outputs are unchanged, otherwise stay running).
- **Test:** add a test with exactly the probe above (preview-video, torn mp4, `SystemExit(1)` → resume says
  `preview-video … did not finish`), plus the existing qc exit-1 test kept green.

### P2-2: `reel next` now crashes when `main_footage` is not a string (regression in the read-only orientation verb)
- **Where:** `run_state.py:351-357` (`_footage`: `Path(mf)` on whatever `edit-decisions.json` `global.main_footage`,
  `timeline-spec.json` `main_footage` or the range holds). It is called from `cli.next_doc` via `preflight_problem`,
  with no guard.
- **Reproduced (probe):** `01_analysis/edit-decisions.json` = `{"global": {"main_footage": 5}}` (or `["a"]`) →
  `next_doc` raises `TypeError: argument should be a str or an os.PathLike …`. The same happens for a timeline-spec
  `main_footage` that is a dict.
- **Impact:** `reel next` / `reel run-state` crash. `reel board` shows that item as an error, and `reel brief` says
  "next step: could not be worked out". This hits a Claude-authored file (AUTHOR edit-decisions), and the step that
  would explain the mistake (`reel plan`) is exactly what `reel next` can no longer name.
- **The test's claim:** `test_read_only_and_never_raises` covers only torn JSON, not wrong types.
- **Fix:** in `_footage`, keep `mf` only when `isinstance(mf, str) and mf.strip()`. Also take `.get("global")` only
  when it is a dict.
- **Test:** add the wrong-type cases (int, list, dict; `global` as a list) to `test_read_only_and_never_raises`.
- **Not BL-04's:** a `source.json` that is a JSON list crashes `next_doc` already in `motion_config.is_motion`
  (pre-existing, not this card).
