## Findings

### P2-1: the "Source-R naming rule" test passes without scanning anything when no key is present (false green on a done criterion)
- `whynot-cut/tests/test_legal_notices.py:127-130` runs `identity_scan.py scan --root docs/legal/notices` and only asserts `returncode == 0`.
- `tools/identity_scan.py:1078-1084`: with no key, the scanner prints `skipped: no key` and exits 0.
- I ran the same command on this PC (`heavy.sh job peer-BL-03-idscan`). Output: `{"skipped": "no key", "hits": [], "files": 0}`.
- So in h2's suite and in mine, `test_identity_scan_is_clean ... ok` was reported without scanning a single file. The module docstring (line 7) says "it is skipped without the key", but the test never calls `skipTest`. A done criterion therefore shows as verified when it was not.
- The repo already has a convention for this. `test_identity_scan.py:622-628` (`test_real_tree_passes_with_the_owners_key`) calls `skipTest` when no key is present, and when a key is present it scans the whole repo, including `docs/legal/notices`.
- **Fix (choose one):**
  - (a) Add `--json`, parse stdout, and `self.skipTest("the owner's identity key is not on this machine ...")` when `"skipped"` is in it. Otherwise also assert `files > 0`.
  - (b) Simpler: delete this test and say in the docstring that `test_identity_scan.TestRealTree.test_real_tree_passes_with_the_owners_key` covers `docs/legal/notices` (the repo-wide scan).
  - Either way, the report must not claim this check passed on a PC without the key.

### P2-2: the master's Answer ("do not send before BL-02 is merged" goes into the templates' review checklist) is not in any file. The GPL letter also states something that is not true today.
- `grep -r "BL-02\|checklist" docs/legal/notices` finds nothing. The report put the note only in its own "Not done" section (`inbox/h2/2026-10-20-1350-BL-03.md:23`), so it is lost once the branch merges.
- Why it matters: `gpl-compliance-request.en.md:16` / `.ar.md:16` assert "Each source file carries an SPDX licence line and a copyright line" / «وكل ملف مصدر يحمل سطر رخصة SPDX وسطر حقوق النشر».
- On the base of this branch that is false. For example, `whynot-cut/engine/reel/cli.py` has neither line (grep count 0), and only about 200 files carry SPDX.
- It stays false after BL-02 too. BL-02's `spdx_headers.py` deliberately skips third-party files, fixtures, generated files and the sha256-pinned files: installer `install.ps1` / `bootstrap.ps1`, and the guide-ar chapters, `index.html` and `styles.css`.
- A false statement of fact in a letter sent to an opponent weakens the sender, and the recipient can check it in one minute.
- **Fix (inside the fence):**
  1. Add a short "Before sending" checklist to each of the 4 templates, under the banner or above Attachments, in that file's language. It should include at least:
     - the release being cited contains BL-02's `LICENSE` and the SPDX/copyright headers (that is, BL-02 is merged and released);
     - every `{{...}}` is filled;
     - a lawyer has read it.
  2. Soften line 16 in both GPL files to something true, such as "Our source files carry SPDX licence and copyright notices" / «وتحمل ملفات المصدر لدينا إشعارات الرخصة (SPDX) وحقوق النشر». Do not use "each".
  3. Optionally, assert in the test that the checklist heading exists in all 4 files.

### P3-1: the GPL remedy asks for more than the GPL requires
- `gpl-compliance-request.en.md:29` / `.ar.md:28` ask the recipient to "publish the complete corresponding source code". GPLv3 requires the source to be conveyed to every recipient of the object code (through the licence's conveying-non-source-forms terms), not necessarily published to the world.
- A lawyer would likely narrow this. **Fix:** "make the complete corresponding source code available to every recipient of {{their_product}}, as the licence requires (for example by publishing it), under the same licence, …". Keep it free of a section number so the article test stays green.

### P3-2: the docstring's run line points to the old 2.x venv
