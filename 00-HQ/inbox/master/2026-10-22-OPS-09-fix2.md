## Known limits (written down; no fix rounds left)
- **Stamp evasion:** a writer that restores the old mtime too (`os.utime`, `touch -r`, some archive extractors) is
  not seen.
- **Stamp gap:** an untracked file that is created and deleted entirely inside the run window is not seen.
- **Stamp effect:** a test that writes inside the repo makes every run "not cached" (fails safe).
- **PATH-based skips** (`shutil.which` finding shellcheck, PSScriptAnalyzer, etc.) are not in the key. After installing
  or removing such a tool, use `--fresh`.
- **Runtime id** (r1 P3-8): an in-place package reinstall doesn't change the key; use `--fresh`.
- **Ignored files** (local configs, downloaded fixtures) are not in the key.
- **Atomic writes:** each write is atomic, but two runs that finish together can still overwrite each other's
  `durations.json` (last writer wins). Durations only steer ordering; there is no corruption and no wrong result.
- **heavy.sh:** the 2-slot reserve applies only while the psuite's ticket says `heavy`. While it waits for RAM or for a
  running suite, jobs keep only 1 free, as before. Once RAM drops, the reserve becomes 2 on the next poll.
- **Out of fence (r2 P3-3):** the control-center `runlog.py` regex `(suite|job|gpu)` doesn't label `psuite`. Fix it in
  the PLAYBOOK switch step, as the reviewer suggested.
