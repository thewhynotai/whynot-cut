## Design note (for the card's Design section)
Workers now inherit TEMP, TMP and TMPDIR **unchanged** from the parent. `tools/test.sh` sets them exactly as for the
serial run. There are no per-module TEMP folders any more.
- **Why:** semgrep (`tools/security/scan.py`) exits 2 with no output once TEMP is longer than ~46–48 chars. The
  per-module TEMP was 54–67 chars, while serial uses 28 (`D:\ClaudeData\Temp\wnc-tests`). That made 10
  `test_security_scan` tests fail in parallel only.
- **Same path lengths as serial.** A TEMP shorter than serial is forbidden, because it could turn a serial failure
  into a parallel pass.
- **No loss of isolation.** Each test module already makes its own sandbox inside TEMP. A collision between processes
  can only add failures (the safe direction), never hide one.
- **Where records and logs live:** still under `<gettempdir>\wnc-par-<pid>\<tag>\`. That run folder is not the tests'
  TEMP.

Logs:
- A module with a problem (failure, error or unexpected success) keeps its `worker.log` and `record.json`.
- An incomplete module keeps them too, as before.
- Only clean modules are tidied.
- For each kept log, the tool prints `parallel: log kept: <tag>: <path>`. This line comes before the report, so the
  verdict stays the last line, and it is not stored in the cached report.
- Relabel re-runs are tidied as before. They share one `relabel` folder, and the module's first-run log is the one
  that is kept.

## Known limits / notes
- **Kept logs are never removed by the tool.** Kept run folders (`wnc-par-<pid>`) stay in TEMP until someone deletes
  them. This is intended, for diagnosis, but they can pile up after many failing runs.
- **Shared TEMP between workers.** Workers now share one TEMP, exactly like the single serial process. A test that
  writes a fixed file name directly in TEMP (not in its own sandbox) could collide with another module. That can only
  add a failure, never hide one.
- **No mutation run.** This is the LIGHT-tier bar, though this is round 3 by master decision. The fresh review is up
  to the master.
- **Equivalence:** the serial reference on fb28e3f stays valid for every module except `test_test_parallel`, because
  only the tool, its test and a fixture changed (see the stat above). The parallel equivalence run on 97b076f is still
  to be done by the master.
