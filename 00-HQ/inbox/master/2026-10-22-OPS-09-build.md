## How it works
- `tools/test.sh --parallel N [--fresh]` resolves the interpreter and TEMP exactly as before, then runs `"$PY" $FLAG -B tools/test_parallel.py --workers N ...` with `PYTHONDONTWRITEBYTECODE=1 PYTHONUTF8=1`.
- One worker process per module: `[same python] [-s if the runtime uses it] -B -W error::ResourceWarning`, `PYTHONUTF8=1`, `PYTHONDONTWRITEBYTECODE=1`, cwd = repo root, its own TEMP/TMP/TMPDIR under `<TEMP>/wnc-par-<pid>/<tag>/tmp`. The worker loads its module with `unittest.TestLoader().discover(tests_dir, pattern="<module>.py")` (the same loader path as serial, so import errors still show up as `_FailedTest` errors). It runs the module with `TextTestRunner`, and writes a JSON record atomically (`.part` then `os.replace`): `complete: true`, tests_run, skipped, expected_failures, problems (kind/id/description/traceback), duration.
- Parent: the worker's stdout/stderr go to its log file. A module counts only when the record exists, passes a strict schema check, AND the worker exit code is 0. Otherwise the run is INCOMPLETE (exit 2): the output names the module, the reason, and the last 30 log lines, and nothing is stored (no cache entry, no durations).
- Output: FAIL/ERROR blocks (unittest format), `Ran N tests in Xs`, then `OK` / `OK (skipped=K)` / `FAILED (failures=F, errors=E, skipped=K)`, or `INCOMPLETE (...)` instead of OK/FAILED on exit 2. Then the `parallel:` lines: workers, wall, modules, serial_lane, ram_peak, the 5 slowest modules, and one `parallel: label: <id>: <label>` line per failure.
- Strict rule: every FAIL/ERROR of the first run counts. Each one is then re-run alone, serially (`--only <id>`), only to choose its label; the exit code and the FAILED line are computed before labelling and never change.
- RAM brake: before each start, if RAM ≥ 85 % it prints one `RAM brake` line and polls (every 2 s; `WHYNOT_PARALLEL_POLL`). Nothing is killed. RAM is read with GlobalMemoryStatusEx (Windows), `sysctl` + `vm_stat` (macOS) or `/proc/meminfo` (Linux); when it can't be read, it says so once and goes on. Every 5 min it prints `still running: <module> (<s>)`.
- Cache: key = sha256 over (HEAD sha, hash of `git diff HEAD --binary` + untracked non-ignored files under whynot-cut/ and tools/ with their contents, runtime = executable|version|-s, the tool's own file hash as its version, the tests dir, the lane), shown as `<sha12>-<hash20>`. When there is no git state, the cache is not used. Folder: `$WHYNOT_SUITE_CACHE`, else `D:/ClaudeData/suite-cache` if `D:/ClaudeData` exists, else `<WHYNOT_HOME or ~/.whynot-cut>/suite-cache`. Durations live in `<cache>/durations.json`.

## Decisions and why
1. **Test hooks:** `--repo`, `--tests-dir`, `--serial-lane "<comma ids>"` (empty = none), plus the env vars `WHYNOT_SUITE_CACHE` and `WHYNOT_PARALLEL_FAKE_RAM_FILE` (a file holding the RAM %, so a test can change it mid-run). `WHYNOT_PARALLEL_POLL` shortens the wait in tests. The defaults are the real repo and the card's lane.
2. **Tool version = hash of the tool file**, not a hand-kept constant: any edit to the tool invalidates the cache automatically ("when in doubt, miss").
3. **Missing duration:** estimated as file size × the seconds-per-byte measured on the modules that do have durations. Pure size order only when nothing is recorded. Mixing seconds and bytes directly would be meaningless.
4. **Test package:** any sub-folder of the tests dir with `__init__.py` → refuse, exit 2, name it (safest reading of "say so and exit 2", even if the package holds no tests).
5. **Lane id that matches nothing → exit 2** (a renamed test would otherwise run in no lane at all, unnoticed). A lane id whose module doesn't exist is refused before anything runs.
6. **Exit code rule for workers:** a record plus a non-zero exit code is still INCOMPLETE ("exited by itself").
7. **Unexpected successes** count as failures (as in serial `wasSuccessful()`) and appear in the FAILED line as `unexpected successes=N`. They get no label.
8. **No recursive deletes:** after the run the tool removes only the record/log files it wrote and `rmdir`s the folders if empty. An incomplete worker's log is kept for diagnosis.
9. **Extra unittest args (`-k`, `-p`) are not supported with `--parallel`**: argparse rejects unknown args with exit 2. The card defines `--parallel` as the full suite only.

## Known limits
- The equivalence run on the real repo, the ≤ 30 min wall time, and the heavy.sh `psuite` kind are not done here (master's part). Until then the tool is verified only on fixtures.
- "A total that does not equal the sum": the total is computed as the sum of the per-module records, so it can't differ by construction. Protection is the schema check per record plus "every scheduled module and lane id has a complete record".
- macOS: the RAM reading via `vm_stat` (free + inactive + speculative pages) is an approximation, and it is not run on a Mac yet (Mac CI runs only on push). `os.kill(SIGTERM)` in the killed fixture works on both platforms.
- On Windows, stdout is text mode, so the report shows CRLF line ends like serial unittest output. The cached report text is stored with LF.
- Two `--parallel` runs at the same time are separated by pid folders, but they share `durations.json` (last writer wins). heavy.sh `psuite` is meant to prevent concurrent runs anyway.
- No per-worker timeout (as the card says); a hung module is visible only through the 5-minute `still running` line.
