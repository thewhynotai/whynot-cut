## Pre-mortem (written before building; upgrades marked ⇒)
- Does a protected ACL break `uv`, the Whisper download, or Premiere/AE reading the engine's tmp copies? No: all of them run as the same user (full control). Elevated processes are covered by BA and services by SY. A second Windows account cannot use this engine home, by design.
- Is `%ProgramData%\WhyNotCut\tmp` (09d56c5) still needed once the home is ASCII? Yes, as a fallback for an editor who hasn't moved the home yet. `ascii_stage_roots` already puts `<home>\tmp` first when the home is ASCII. It is outside this fence; I didn't touch it.
- ⇒ The card asked for an icacls-text fixture "English AND localized, read by SID". I read SDDL instead (`GetNamedSecurityInfoW`): SIDs and fixed aliases, identical on every Windows language, so one fixture set covers both. icacls text shows localized account names (e.g. "VORDEFINIERT\Benutzer"), which can't be read by SID without a per-language table. **Deviation from the done-criterion wording; the intent (localization-proof, by SID) is met.**
- ⇒ The command shown to the editor quotes each grant: in PowerShell a bare `(OI)` runs as a command, and in Git Bash `*` expands.
- ⇒ The suggestion stays at a drive root: there, other accounts can't rename or delete the locked folder (that needs DELETE on it or DELETE_CHILD on the root, and AU has neither). A deeper home with an open parent could be swapped by renaming the parent: a known limit, below.
- ⇒ Decision: an EXISTING home that is a junction (e.g. `~/.whynot-cut` moved to D:) only gets a doctor line. Setup still checks its target's ACL and refuses only when that is open. Setup refuses to CREATE a home under a linked parent. Reason: refusing every junctioned home could break dev PCs and existing installs.
- ⇒ Owner check added: a folder another account made first can't be fixed by its user.

## Risks and notes for the reviewer
- Known limits (LIGHT tier):
  - A home deeper than a drive root, with a parent other accounts can write to, could be swapped by renaming the parent. Doctor checks only the home and its direct parent for links, not the parent's ACL.
  - Items planted deeper than the top level while a home was open are not found. Doctor checks only top-level owners, and the fix text points to a new empty home.
  - A USB hard disk can report as "fixed" (`GetDriveTypeW` = 3) and could be suggested.
  - The doctor command leaves an explicit entry it cannot read in place (a conditional ACE); doctor keeps flagging it.
  - The link check is Windows-only, to keep macOS unchanged as the spec says.
- Patch location: the spec says `hooks\BL-16\`, the card says `00-HQ\inbox\h1\BL-16-patches\`. I followed the card.
- `reel setup` now refuses an existing open home outside the profile. Installs whose `WHYNOT_HOME` is such a folder get the exact icacls command on their next setup, which is intended. Default homes under the profile are unaffected.
