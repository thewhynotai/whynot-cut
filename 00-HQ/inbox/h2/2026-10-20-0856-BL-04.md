## Risks and notes for the reviewer
- **Spec deviation to rule on:** the spec says "`next` / `stale_steps` list preflight first". The rule is in `next_doc`, NOT `stale_steps`. In stale_steps it made `reel handoff --delivered` refuse a QC-passed item with no preflight.json (`test_cli_consistency TestDelivered.test_delivered_after_qc_and_handoff` failed). The finding is about what `next` lists, not about the delivery gate. A test pins that it is not a stale step.
- **"Changed input" uses mtimes, not a hash of inputs** (per the binding pre-mortem: cli.stale_steps only). So a touch without a content change also re-runs downstream, and the graph has no transcript→plan or preflight→transcribe edges. That is the existing `reel next` behaviour, unchanged here.
- A recorded output that is valid but changed since its stage finished is only listed under `run_state.changed`, never re-run (re-running transcribe would undo the transcript corrections; conform rewrites preflight.json). Only missing, empty or unparsable-JSON outputs, or a stage killed mid-run, re-run.
- `reel run-state` answers for the start of a session. It cannot tell a stage that is running right now in a parallel subagent from one that was killed. Known limit; the skill text says when to use it. A pid check (writer_lock.pid_alive) would close it.
- Not recorded per item: AUTHOR files (written by Claude, no verb), discover/client-db (client level), ae-probe (machine level). `reel next` covers them by existence. Running the frames alone (ppro-frames / motion-frames) leaves no record unless cut mid-way; `verify --record` finishes the proof stage.
- With the patch, every stage verb writes `output/projects/<ID>/run-state.json` plus `run-state.json.lock` (the same pattern as project-status.json.lock). The reviewer found no test that compares a project's exact file list; client_move already skips `output/**.lock`.
- `reel next` / `reel board` read the spec, edit-decisions and preflight once more per clip (preflight_problem). Watch the board's 5 s budget on a big client.
- Mac: the paths are relative POSIX; there is no macOS-only code. "Live checks needed — Mac": `reel run-state` on a clip after a cut, plus NFD Arabic file names (the preflight name check compares resolved paths exactly as premiere_xml does).
