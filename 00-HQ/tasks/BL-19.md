## Goal (the editor's view)
An editor moves or clones a client folder with `reel client-move` / `client-clone`. Today every approval on the
moved clip is voided and NEEDS-YOU asks the editor to approve the transcript, plan, motion script and reels plan
again, although nothing in them changed except the folder. After this card, the same content in a new folder
keeps its approvals, and any real change to words, cuts or timings still voids them.

## Decision for this card (master)
Build ONE pure helper that every fingerprint can call; wire nothing in other owners' files yourself.
- New module `whynot-cut/engine/reel/lib/root_fingerprint.py`: given the bytes or the parsed JSON of a hashed file
  and the client root, return a canonical form where every path under that root is written root-relative with `/`
  separators (case-folded drive letter on Windows), then a hash of that form. Paths outside the root stay as they
  are. It also exposes `accept_legacy(old_hash, raw_bytes, root)` for the "accept the legacy hash once, then
  re-seal" rule.
- Each call site (plan.py `plan_fingerprint`/`spec_fingerprint`, transcribe.py `words_fingerprint`,
  cut_proposals.py `words_sha1`, motion_plan.py `fingerprint`, reels.py `reels_plan_fingerprint`, cli's transcript
  record, and client_move.py's voiding of ruling (c)) is changed ONLY as a patch, one file per owner.

- **Holes and risks:**
  - JSON key order and float formatting must be canonical (sorted keys, no re-rounding of ms), or the same file
    hashes differently after a rewrite.
  - Media `pathurl` entries (`file:///…`, URL-encoded) must normalise the same way as plain paths.
  - A file that embeds the root inside free text (a note, a caption) must NOT be rewritten: normalise path-valued
    fields only, by key, and list the keys in the module docstring.
  - Never touch a real client folder: fixtures and temp dirs only.
