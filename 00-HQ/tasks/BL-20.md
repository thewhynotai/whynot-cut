## Pre-mortem (written by the master, upgraded by the builder)
- **Will it work end to end for its real user (the executor at the gate)?** Only if a clean answer is trustworthy:
  a parse error, a missing tag or a missing git must never look clean (exit 2, said plainly). That is why those are
  acceptance lines. It must also not drown the executor: ~450 skip sites exist today, nearly all platform/tool, so
  the default output shows the per-class counts and lists only `dated` and (in `--since` mode) new `unknown` sites;
  `--all` lists every site.
- **Cheap smart additions (taken into acceptance):** the 61feeb2 regression fixture; a `--json` report the gate
  record can attach; the "Order at the gate" text in the report so the executor wires it in one step.
- **Prerequisites / must be ready first:** none. The `v3.0.0-p3.1` tag exists in the repo; the tool is new files only.
- **Holes and risks:**
  - The `except ImportError` pattern hides the marker away from the decorator: the classifier must follow the
    condition's name back to where it is assigned in the same module (that is exactly the 61feeb2 shape).
  - A reformatted or moved old skip shows up as "added" in `git diff`: it is listed as `unknown`, which is safe
    (the executor reads it); write this as a known limit, don't try to diff moves.
  - The heuristics for `platform/tool` are a helper, not a proof. A `dated` marker always wins over a
    `platform/tool` look (an ImportError skip with `_PENDING` is `dated`, even though ImportError looks like a tool
    skip).
  - It is dev-only. The plugin zip is built from `whynot-cut/`, so a file in the repo's `tools/` is not in it; the
    Mac hand-off is a repo clone, where it is harmless. Confirm it by reading how `tools/release.py` builds the
    Windows zip (do not run a hand-off), and say so in the report.
  - Heavy queue: YIELD.txt has the prefix `bl`; label your suite `h2-BL-20` (starts with `h2`), and do the §3d
    check as in the BL-04 Answer (2026-10-20 09:40) before queueing.
