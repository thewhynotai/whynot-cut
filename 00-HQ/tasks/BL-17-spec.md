### BL-17 [later]: A second install's SessionStart writes the first install's pointer files (found by the release track 2026-10-18)  [Gate 5 value: med]  Model: opus
- **What:** `plat.options_file()` and `session_context.plugin_root_file()` are fixed at `~/.whynot-cut/` (by design, T1.9: the bootstrap pointer has to exist before engine_home is known). Only `WHYNOT_OPTIONS_FILE` moves them. A second WhyNot Cut install on the same account (a dev or try marketplace beside the real one, or 3.0 beside 2.2.1) overwrites `plugin-options.json` / `plugin-root.json` at every SessionStart. The other install's PowerShell wrappers then read the wrong plugin root.
- **Design to decide:** key the pointer files per marketplace or plugin id (for example `plugin-root.<marketplace>.json`, with the wrappers told their id). Or have SessionStart write `WHYNOT_OPTIONS_FILE` into CLAUDE_ENV_FILE when WHYNOT_HOME is set. Either way, keep the T1.9 PowerShell constraint (no path-valued env from CLAUDE_ENV_FILE).
- **Workaround today:** set WHYNOT_OPTIONS_FILE for the try install (the release track does this). Document it in platform-setup.md at Gate 5.
- **It happened for real (2026-10-18 18:24):** BLD-B's BL-15 live CLI smoke on a snapshot rewrote the real `~/.whynot-cut/plugin-options.json` and created `plugin-root.json` pointing at a temp snapshot. The executor moved the stray file aside (D:ClaudeDataTempstray-20261018). Every dev or try smoke now sets WHYNOT_OPTIONS_FILE + WHYNOT_HOME into a temp folder and lists the home before and after. Consider raising this to Gate 5 high: a dev machine is exactly where two installs live.
- Risk: normal (affects only multi-install machines: our own and power users).
- **More of the same family (REL-PREVIEW, 2026-10-19):**
  - (1) A second engine home still reads the SHARED `~/.claude/whynot-cut.local.md` (common.clients_root), so its doctor listed the real clients root and offered `doctor --fix --all-clients` (cli.py ~1370-1384). Never offer that against a clients root this home did not set.
  - (2) Claude Code APPENDS plugin bin dirs to PATH, so a session started with 2.2.1's bin already on PATH runs 2.2.1's `reel`. Doctor's "wrong reel first on PATH" check catches it; document it in platform-setup.md.
